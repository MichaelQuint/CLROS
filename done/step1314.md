# Step 1314 - Passive TCP handshake ownership development

## Summary

Compose the existing passive planner, connection table owner and backlog for
#149's implementation within shared integration #734. The TCP fast filter passes
209 checks across 26 fixtures, including eight new owner checks and one pending
reply writer check. These are host packet/clock/TX models. #149 remains open and
acceptance-blocked on #148/#691 and its own live packet/native/guest evidence.

## Why

The existing low-level handshake intentionally enters Failed after a bad ACK;
applying that temporary result directly would destroy a real pending connection.
Successful serialization also is not TX admission, and a successful final ACK
cannot establish before backlog admission. Preserve those boundaries using a
small per-connection owner rather than a second TCP table or socket abstraction.

## Files changed

- `src/OS.Kernel/Net/TcpPassiveConnection.cs`: one caller-retained, noncopyable
  unmanaged controller over the existing opaque table handle. Begin validates a
  SYN and reserves its tuple before attempting the reply. Initial TX pressure
  retains pending state with zero accepted attempts; an ACK cannot establish
  before any SYN-ACK was accepted. A synchronous TX callback must copy the frame
  before returning; no borrowed packet is queued. A trusted monotonic nanosecond
  callback drives a fixed original lifetime, one bounded due retry per call,
  at most eight accepted initial/scheduled attempts and a lifetime at most 60s.
  Duplicate replies retain the original retry schedule/deadline and sequence
  space. Full/short output consumes no attempt. Exhausted retries still allow a
  final ACK until the hard deadline. Backward/overflowing clocks are rejected.
  Invalid ACKs discard a temporary planner. Backlog full/duplicate/corrupt/order
  rejection preserves the pending table entry. After admission, a nonfallible
  assignment commits the prevalidated table transition and candidate planner;
  exclusive metadata ownership and nonreentrant callbacks are required. Expiry
  or explicit pending cancellation closes/releases/scrubs table metadata. Fatal
  TX retains faulted ownership for explicit cleanup. Established handles/backlog
  entries pass to the later stream/close consumer for final release. Reject
  copied/stale state, aliases, invalid options, oversized frames, multicast MACs
  and IPv4 fragmentation; existing parsing rejects IP options. No unchecked
  guest pointers, dynamic allocation, socket/PAL or data-stream layer is added.
- `src/OS.Kernel/Net/TcpPassiveOpenHandshake.cs`: accept an exact duplicate SYN
  in SynReceived, retaining the original IRS/ISS; a different IRS is rejected.
  Existing terminal low-level rejection contracts remain, so live owners stage
  copies rather than publishing a failed temporary planner.
- `src/OS.Kernel/Net/TcpPassiveIpv4FramePlanner.cs`: nonmutating pending SYN-ACK
  serialization using the existing checksum/frame helpers and saved identity,
  window, TTL, identification and sequence space. No fake incoming SYN is needed.
- `tests/OS.HostTests/TcpPassiveConnectionTests.cs`: eight focused owner cases
  use independent Ethernet/IPv4/TCP byte vectors and independently computed
  checksums. Cover invalid ACK then good ACK, two independent table lifetimes
  under backlog pressure, duplicate endpoint without generation authority,
  exact duplicate/retry bytes, uint.MaxValue sequence wrap to zero, full initial
  TX, short/full retries, original deadline expiry, stale/copy/alias/capacity
  controls, invalid options/clocks/fragments, fatal cleanup and 10,000 warmed
  allocation-free begin/cancel lifetimes.
- `tests/OS.HostTests/TcpPassiveIpv4FramePlannerTests.cs`: pending writer rejects
  listen/established states and short output without changing state/output.
- `docs/networking.md` and `.gitea/backlog/clros-issues.json`: development evidence
  and limitations only; no dependencies, acceptance labels or desired state change.
