# Step 1058 - Bounded nonthrowing exception-type predicate

## Summary

Implements #575's host-only prerequisite for #90 handler search. The predicate
compares an original retained object's method-table identity with a validated
target and its base hierarchy. It reports admitted match/nonmatch separately
from invalid authority, malformed metadata and unsupported type forms.

## Why

Real exception search needs a nonthrowing type predicate; the current exported
helper still halts. Accepted layout, allocation and module contracts permit
this independent leaf while unwind and diagnostics acceptance runs elsewhere.
It introduces no dependency on full casts, constructor failure caching or the
unaccepted unwind guest profile.

## Evidence boundary

This predicate admits canonical, non-generic fixed classes with no extended
flags and at most 32 same-image immutable prefixes per chain. It validates both
complete chains before returning success; a bad later ancestor cannot preserve
a partial match. It does not resolve imported/tagged/relative types, general
assignability, arrays, strings, interface targets, value types, dynamic types,
finalizers or generic types. Inputs need not derive from System.Exception.

Caller-provided mapping/compiler provenance and exclusive stable lifetime remain
obligations. Collecting mode checks current allocation identity; externally
reset/freed/reused noncollecting ownership lies outside its contract. No
snapshot authenticates arbitrary type bytes, and no object root or lifetime
extension is supplied. Host-controlled metadata is fixture evidence only.
`RhTypeCast_IsInstanceOfException` remains halting, and no completion gate,
Kestrel/cloud readiness or full exception milestone is promoted.
