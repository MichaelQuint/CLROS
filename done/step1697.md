# Step 1697 - Discover host producer outputs from the build graph

## Summary

The host runner now consumes the selected MSBuild project outputs instead of a
fixed list of companion names and bin/Configuration/net11.0 guesses. The r41
candidate passes 57 focused checks, with unchanged inputs and zero reuse.

## Why

Moving files or adding a transitive helper should not silently remove its bytes
from resume validation. The executing producer records its actual output graph;
discovery supplies inputs, while hashes and independent assertions decide whether
those inputs and results are admissible.

## Files changed

- HostProjectOutputs.targets recursively queries resolved project references,
  including ReferenceOutputAssembly=false helpers, preserving selected output
  paths, project identities, configuration, platform, framework and runtime ID.
- OS.HostTests.csproj embeds that graph before its compiler receipt is captured.
- HostProjectOutputs and its Output record reject missing, changed, ambiguous,
  escaped or malformed producers. Identical diamond references are allowed.
- HostTestFingerprint snapshots the selected directories, including nested
  runtime files and unknown sidecars. Declared hashes join the same captured
  bytes; boundary checks also detect added or removed output files.
- HostToolProcess resolves built tools through the embedded graph.
- HostProjectOutputsTests and HostResumeTests exercise these boundaries.

The restricted EFI project and root build imports are unchanged.
