# Step 1290 - Call-local pool authentication and released-owner teardown

## Why

R16 stops near its300-second driver ceiling, after actual application EH output
and five live threads. Its last logged time is299856487800ns after Begin;
the next attempted supervisor time is not recorded. Budget expiry is consistent
with the trace, not independently established. Every pool audit also repeated
the same native code/descriptor/CPU/borrow authentication for each of162 pages.
The private common admission and read-only leaf walk can remain within one
serialized IRQ-off BSP call without repeating that invariant work per page.

An independent teardown defect is concrete in source: LinuxNativeRelease sets
control Phase5, but CooperativePhase remained2. The later restoration walk
therefore called LinuxNativeOwner, whose correct active Phase1..4 restriction
rejected the released process. R16 does not identify its first cleanup return,
so this source defect is not retroactively claimed as its recorded first failure.

## What changed

- `CooperativeAdmitPool` contains the unchanged common owner/code/CPU/borrow
  authentication. `CooperativeWalkPoolLeaf` retains address/alignment, table
  bounds/cycle, physical identity, WB and4KiB leaf checks. The ordinary
  `CooperativeFindLeaf` wrapper still authenticates every standalone call.
- Only CooperativeAuditPool authenticates once per invocation, then validates
  every PTE, guard and permission. The admitted memory/root remain call-local;
  the read-only loop calls no callbacks and IF is excluded by the admitted flags.
  No validity survives a return, transfer or mapping change. Publication and
  entry-rewrite callers keep the full wrapper.
- After actual release, `LinuxNativeBeginTeardown` requires the exact retained
  control, Phase5, no active attachments/workers/current/handoff/IRQ/timer
  borrows, released timer queue, restored gateway Phase2 and original TSS
  RSP0/IST4. Only then does CooperativePhase advance to5. Active native-owner
  admission remains Phase1..4; common hardware and PTE checks still apply.
- First-stop diagnostics distinguish budget(1), failed state(2), idle failure(3),
  empty untimed waits(4), step exhaustion(5) and failed clock read(6). They record

  A separate cleanup rejection stage1..10 identifies the failing release,

  the real worker exit/reap drain.

All time, epoch, step, physical-page and thread bounds remain unchanged. App
