## Why

The accepted Hello trace creates its finalizer and signal-handler threads before
stdout. Requiring Hello in #685 while #686 depends on #685 was a semantic
deadlock despite an acyclic JSON graph. Requiring real .NET threads in #686 also
implicitly required the later signal ABI. The revised mechanical prerequisites
avoid pretending that mocked threads or signals start an upstream runtime.

Trace `NativeAotHello-trace.3144` line 66 reserves 8,234,266,624 bytes with
`PROT_NONE`, beyond the current 4-GiB user range. #684 must separate sparse
virtual ownership from physical commitment/page-table quotas and either admit
a safe larger user VA layout or qualify an explicit smaller configuration/real
fallback. It also records the existing diagnostic 64-call boundary. No changed
payload or disabled protection may silently substitute for the accepted input.
Lines 191-200 and sibling trace `.3146` require real fd duplication, pipe
creation and blocking signal-thread reads before Hello output at lines 225-228.
Pipes therefore belong before first Hello, not only in the later epoll work.

M09-009 now consumes scheduler waits directly rather than requiring unrelated
event/mutex PAL implementations. M09-010 preserves application FS/TLS and kernel
GS; upstream NativeAOT owns managed thread statics. M09-011/012 acceptance now
describes real upstream GC and Task/timer behavior rather than generated
collector/device boilerplate. Separately qualified focused fixtures prevent a
GC-only smoke from requiring the all-in-one runtime app's later Task/timer work.

Canonical source paths now use `src/OS/Boot/EfiEntry.cs`; #684 owns the real
mapping/gateway/transition files and split integration admission files. Early
host-only M10 app/publish/package tickets no longer own EFI integration. Open
M16/M10 references use the accepted .NET 10.0.12 and musl 1.2.6 revisions.
