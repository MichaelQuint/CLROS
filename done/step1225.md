# Step 1225 - .NET 11 migration and lifecycle handoff

## Summary

Qualification in progress. This record will be completed from the retained
receipts before merge. It does not yet accept this migration.

The user selected .NET 11 for the OS, compiled host tools and first guest
NativeAOT application milestone. The migration is tracked by #727. Lifecycle
#188 remains the next implementation slice, with its ownership and acceptance
contract repaired before the development lane is released.

## Why

The Visual Studio Insiders update changed the installed SDK and native linker.
Changing TFMs alone is insufficient for this freestanding runtime: the new
compiler changes module registration, interface dispatch and array helper ABI.
The same migration also requires a fresh upstream Linux payload audit. Prior
.NET 10 receipts remain historical and are not relabeled.

  `11.0.100-rc.2.26504.105` and runtime/ILC/ILLink
  `11.0.0-rc.2.26504.105`. SDK roll-forward is disabled; prerelease admission is

- `tools/OS.Tooling/NativeAotPayload.cs` exclusively leases app caches during
  qualification, archives each app's old `bin`/`obj`, rejects reparse-point and

  managed/native outputs. Package evidence includes the exact runtime,
  compiler, trimmer and native dependency closure. `MinimalApiSmoke` supplies
  explicit source-generated JSON type information for `/config`.
- QEMU uses an explicit Nehalem x86-64-v2 CPU without enabling AVX/XSAVE state
  outside the existing context contract. The entropy-negative CPU continues
  to exclude RDRAND/RDSEED.
- `.gitea/backlog/clros-issues.json`, README, agent guides and canonical docs
  adopt the .NET 11 NativeAOT-first target. Historical receipts, stable schema
  identifiers, Linux errno/fd semantics and the separate `OSHost_*` ABI remain
  distinct. CoreCLR is a later workload route.

The lifecycle handoff now specifies one BSP/CPL0 cooperative owner; Entry and

park/wake/cancel/exit; independent wait identities with fail-closed exhaustion;
repeated timer epochs and dirty-wake handling; true all-parked hardware wake;
zero-delay yield; one pending joiner with self/cycle rejection; completed-join
retention until reap; deferred cancellation at start/safe points; single-winner
completion and capacity checks before deadline unlink; and off-stack teardown
before identity/stack reuse. Exact SharpOS references, ownership paths, host
controls, original native review and three fresh guest captures are specified.
No #188 implementation is included here.

## Failures

- Development builds, stale source/fixture expectations and rejected native
  admissions are retained in the artifact roots. Shared contract repairs do
  not weaken unsupported-case rejection.
- The first filtered-catch preparation rejected changed compiler-generated
  bodies. Original disassembly established the new four body identities and
  relocation fields; the verifier was updated with additional semantic
  negative controls, then a fresh r03 capsule was prepared and reviewed.
- Linux r01 published and ran but emitted IL2026/IL3050 warnings from the
  implicit JSON overload. The app now supplies explicit generated metadata.
- Linux r02 reused old Kestrel native output despite changed source with
  preserved timestamps. Its emitted success is explicitly rejected. The
  subsequent r03 run was stopped with owned process cleanup before ILC; it
  remains failed. A successful `dotnet clean` had left old DLL/object files,
  demonstrating why cache archival and fresh-output checks were necessary.
- The final Linux run's competing qualifier was rejected with
  `native_qualification_busy` before creating its output directory. This
  verifies the cooperative lease across processes; manual builds still must
  remain idle during qualification.

milestone. Bounded no-stdlib GC/EH/scheduler diagnostics do not qualify general

allocator ancestor retains a tight bounded diagnostic stack budget, not a
general-purpose stack allowance. Five allocation-negative preparations receive
native-only review; without their separate strict terminal observer they are
not counted as successful QEMU captures. Unrerun historical profiles retain
their original .NET 10 evidence and require current qualification when used.
