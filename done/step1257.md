# Step 1257 - Opt-in user IRQ capture and restored-kernel scheduling

## Summary

Development source for #687/#733 now admits an explicit M16-009 workload
request, `env.CLROS_USER_IRQS=1`. Absent/0 remains disabled; malformed or duplicate
requests fail closed. The retained process/signal policy requires user IF=1 in
this mode and IF=0 otherwise. Kernel callbacks remain IF-off. Clone inherits the
same policy; checked sigreturn cannot disable it through user-edited flags.

The private E1 gate uses owned IST4 and a separate stub in the existing 2048-byte
full-capture region. It admits only a genuine CPL3 frame, pushes positive vector
225 and zero error, then saves the actual user RAX, every GPR, FX, bases and
hardware frame before scratch use. A separate supervisor-only stack witness
binds capture to the expected IST frame. The owner authenticates private IDTR/
GDTR/TSS/gates, original kernel root, current generation and SWAPGS base envelope.
FF uses the independently verified register-neutral spurious leaf. An unexpected
CPL0 E1 on the private user IDT retains ownership in an IF-off halt loop.

Each prepared user excursion borrows the existing APIC one-shot and a separate
IRQ-epoch deadline for the actual selected worker. Real acknowledgement drains
that exact entry and advances the epoch. HPET remains the sole process nanosecond
clock. User capture is copied to the current thread image before gateway cleanup
overwrites its scratch area. The gateway restores its original kernel envelope;
only the subsequent genuine captured kernel CALL may commit KernelThreadTable
Yield. Pending signal delivery uses the existing checked resumption boundary.
There is no synthetic syscall, gate completion, handler or CALL context.

If an ending syscall beats the one-shot, the still-bound worker waits through
the existing STI/HLT/CLI leaf on the guarded native switch stack. A distinct
kernel IRQ admission checks its exact RIP, selectors, saved/current flags,
selected generation, switch-stack RSP, actual IST frame and restored descriptors.
Acknowledgement precedes APIC restoration, IST release and Park/Exit/Yield.
Restore never treats masking a pending IRR as quiescence. Partial/failed
ownership remains retained until actual safe restoration; no guessed wake or
handoff is published. Existing 128-epoch/512-dispatch bounds remain unchanged.

All fifteen canonical thread/signal/fault packages retain their previous bytes.
The current runner still admits only the eleven original M16-009 inputs, which
omit the new policy. No IRQ fixture or strict IRQ transcript is admitted yet.

## Why

Upstream activation must be able to interrupt user code that makes no syscall.
The prior full GP/PF capture and pending signal support did not provide that
path. Separating a user IRQ from a syscall and preserving the actual restored
kernel scheduling boundary avoids fabricating runtime progress. Draining an
ending excursion is necessary because an IRQ can become pending while C# runs
with IF clear; masking/stopping alone cannot prove its lifetime ended.
