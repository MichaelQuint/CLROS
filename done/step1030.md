## Guest observations

An ordinary development run and a debugger baseline emitted the six exact
start/transition/readiness/pass lines once each in order. Five further fresh
q35/TCG/OVMF guests booted the same EFI from a copy of the same pristine disk.
The artifact-only harness uses loopback GDB hardware breakpoints and checks the
loaded PE header, callback arguments and original arena before injecting a
single controlled change. It adds no production test hooks or source variants.
Each negative run ends at the expected native halt with captured registers:

| Injection | Observed result |
| --- | --- |
| Lower stack canary changed before the entry callback | Transition remains empty, firmware CR3 retained, no post-exit markers |
| Native adoption invoked with the original pre-exit state | Exit-state guard halts before CR3 adoption; no post-exit markers |
| Copied ACPI page's retained leaf entry removed | Owned root adopted; essential-map audit permits only the EBS-return marker and suppresses all later claims |
| Recorded CR3 observation changed before diagnostics | Diagnostic admission rejects it and suppresses every success marker; this injects an observation mismatch, not a CPU CR3-load failure |
| Instruction fetch redirected to absent page zero after adoption | Actual vector14/error0x10, RIP0/CR2=0, owned CR3; owned COM1 fault record; terminal handler on the page-fault IST stack |

The page-fault case leaves all eight canaries intact and consumes the fault
context to reported state3. Fault serial SHA-256:
`20E3729CD4577BE7A734CC66CBD4C270B686D3E5601E1E7D8620B6168A21EAE4`.
`terminal-evidence-review.json` verifies the exact positive/negative marker
records, vector/error/register record, all receipts and unchanged source inputs.
The debugger script follows the primary GDB remote packet contract:
https://sourceware.org/gdb/current/onlinedocs/gdb.html/Packets.html
