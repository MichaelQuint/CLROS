# Step 1340 - Retained Linux epoll and real thread waits

## What changed and why

Implement the measured #690 SocketAsyncEngine epoll subset under owned integration
#737. Share socket/epoll fd integers, dup flags and open-description lifetimes.
Support create/create1, ctl, wait/pwait, packed12-byte events, opaque64-bit data,
level/edge readiness and bounded fair delivery. Watches bind original fd plus
description/inode, so dup close and fd reuse cannot redirect them. Last close
scrubs registrations. Copy failure consumes no pending event.

Real epoll operations borrow their original port description and use kernel
wait-source3. Empty/infinite waits park; real monotonic deadlines return0,
directed signals return EINTR without SA_RESTART, and stolen readiness stages a
new real wait token. Cancellation during Parking retains the borrow until actual
captured park/exit. Metadata joins existing descriptor/thread alias guards;
older EFI profiles exclude these new types/fields behind CLROS_LINUX_SOCKETS.

Refresh observes real TCP queues, send capacity, FIN, reset and shutdown. Normal
closed transport retains HUP/FIN readiness without ERR; consumed reset clears ERR.
The serialized network owner must call PollDescriptorReadiness after transitions.
