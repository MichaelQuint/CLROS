# Step 1316 - Retained TCP send-window development

## Summary

## Why

The original payload writer advances a temporary sequence during serialization
and retains no unacknowledged bytes. A live sender needs bounded copied writes,
distinct oldest-unacknowledged/next-to-send values, actual TX admission and
original validated ACK/window decisions. Negotiate limits from original packets,
preserve receiver ownership and reuse the existing frame/checksum helpers.

## Files changed

- `src/OS.Kernel/Net/TcpSendWindow.cs`: one zeroed caller-retained owner binds
  a fresh established passive handshake and active receiver before payload
  dispatch. Private send storage is 1..32768 bytes, disjoint from all metadata
  and receive storage. Queue copies only available capacity and reports short
  writes. Retain sent/unacknowledged plus unsent bytes in one bounded buffer;
  compact after partial ACK when needed. Pump attempts one new segment bounded
  by MTU 68..1500, actual peer MSS, last advertised absolute right edge and
  output capacity. Only accepted copied TX advances next-to-send/in-flight bytes;
  full/short TX preserves queued state, fatal TX retains cleanup. Acknowledge
  validates original frame/endpoint/checksum/flags/receive sequence before ACK
  progress; process it before receive delivery of the same frame. Out-of-window
  validated ACKs schedule a corrective ACK; malformed packets/resets do not.
  Partial ACKs
  release/scrub only transmitted bytes. Duplicate/old/future ACKs release none;
  future ACK schedules a corrective cumulative ACK. Ordered window updates keep
  stale packets from shrinking/reopening a newer window or growing its absolute
  right edge. Closed cleanup explicitly discards/scrubs retained data and detaches.
- `src/OS.Kernel/Net/TcpConnectionTable.cs`: initialized SND.UNA/SND.NXT metadata,
  preserving the two-argument constructor's no-outstanding-data meaning. Modular
  outstanding distance stays below half the sequence space; zero remains valid.
  Add a send-owner attachment, preserve both bindings across owned metadata
  commits, reject unauthorized send-sequence changes and legacy bypass, and
  block table release until both owners detach. Internal unmanaged layouts change;
  native qualification remains outstanding.
- `src/OS.Kernel/Net/TcpEstablishedStream.cs`,
  `TcpEstablishedStreamIpv4FramePlanner.cs`, `TcpReceiveWindow.cs`: live windowed
  receive admits partial ACKs in the retained SND.UNA..SND.NXT range and preserves
  SND.UNA through receive commits. Strict legacy contracts remain. Share read-only
  original frame validation for the sender without fake receive buffers or
  delivery. Existing packet/checksum writers serialize actual data/ACK frames.
- `src/OS.Kernel/Net/TcpHeader.cs`: bounded SYN option parser; absent IPv4 MSS
  uses 536, NOP/EOL/unknown length-bearing options are handled, malformed/duplicate/
  zero MSS is rejected without publishing negotiation. No options or collections
  are allocated.
- `src/OS.Kernel/Net/TcpPassiveConnection.cs`, `TcpPassiveIpv4FramePlanner.cs`,
  `TcpPassiveOpenHandshake.cs`: capture peer MSS from the original validated SYN
  and current peer window/ordering from the final ACK. Reject changed duplicate
  MSS. Optionally emit configured local MSS in a 24-byte TCP SYN-ACK and reproduce
  it on duplicates/retries; legacy default remains the original no-option reply.
  Configured local MSS above the bounded 1460-byte receive limit is rejected.
  Short configured output preserves pending owner, attempts and hard deadline.
- `tests/OS.HostTests/TcpSendWindowTests.cs`: 13 focused cases use actual host
  handshake/receiver composition and independent packet vectors/checksums. Cover
  copied/short writes, no false TX progress, MTU/MSS/output segmentation, partial/
  duplicate/old/future ACKs, zero/stale windows, wrap, bidirectional piggyback ACK,
  negotiation/final-ACK window capture, configured duplicate/retry replies,
  attachment guards and cleanup in both orders, aliases/copies/stale identities,
  fatal TX and 10,000 warmed queue/send/validated-ACK cycles allocating no managed
  bytes. No real NIC is substituted by those callbacks.
- `tests/OS.HostTests/TcpReceiveWindowTests.cs`: expose its pure independent wire
  builder/checksum helpers internally, adding explicit options/window support for
  reuse by send cases. Existing defaults and all receive tests remain.
- `docs/networking.md`, `.gitea/backlog/clros-issues.json`: development evidence
  only; dependencies, labels and desired open state remain unchanged.
