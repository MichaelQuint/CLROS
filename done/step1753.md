# Step 1753 - Report bounded file-transfer cadence through the strict wire parser

## Summary

Add a host-only file cadence value API to QemuTranscripts, reusing the existing
strict TCP/PCAP reconstruction and independent HTTP header parser. Retain actual
record/time witnesses for request completion, entity progress, cumulative ACK
coverage and the next progress transmission. Keep retransmissions, missing ACKs,
negative intervals, incomplete bodies and capture EOF explicit.

The r204 complete solution build has zero warnings/errors. Four fresh focused
runs pass31 checks, zero reuse, with unchanged5,935 archived inputs/31 producers.
Repository/contracts/diff checks pass. No original capture was evaluated in this
checkpoint and no transfer improvement or guest acceptance is claimed.

## Why

The preserved quiet baseline/fixed pair proves a large diagnostic timing gap but
does not identify every cost. Existing unique-byte ranges omit pure ACKs and
duplicate payload; ordinary service wrappers also require their complete close
and injected-control recipes. A stopped quiet capture needs a separate bounded
reporting entry without weakening those acceptance wrappers or copying a TCP
decoder. Both preserved captures exceed the ordinary4MiB reader policy.

## Files changed

- QemuTranscripts.NativeAotService.FileWireCadence.cs adds
  InspectNativeAotFileWireCadenceValues. Its synchronous inputs are borrowed;
  results copy immutable values and read-only collections. Callers provide all
  admitted guest ports in SYN order and literal GET/path/body identities.
- Associated FileWireTarget, FileWireCadence and FileWirePacketCadence records
  each occupy their own file, inside the required partial containing wrapper.
  Parser module MVID and raw capture hash identify observations, not source or
  execution authority.
- The existing private ServiceWirePackets gets one optional established-packet
  observer after every packet guard, including retry equality and FIN sequence.
  Default callers do no additional allocation/copy/decoding. The observer reuses
  ServiceSelectedPacket and its existing private DTO, then retains scalars only.
- The explicit existing full-disk mode supplies64MiB capture/24MiB aggregate
  logical stream bounds. This API additionally caps ports/targets at32 and
  retained packets/unique ranges at262144 before list growth. Default policies
  and every original parser guard remain unchanged.
- Literal bodyless GET and one200 fixed identity-coded Content-Length response
  are supported per target. Extra exchange bytes, unsupported coding/framing,
  incomplete headers and complete wrong hashes reject. Only contiguous complete
  bodies are hashed. Short or holey bodies expose neither a full hash nor span.
- ACK thresholds use bounded relative sequence positions, preserving uint wrap,
  first cumulative coverage, already-covered retries, and full/partial duplicate
  accounting. The next progress send is chosen in original capture order before
  ACK matching. Earlier sends preserve negative ACK-to-next intervals; missing
  endpoints stay null. These are not RTT or CPU measurements.
- A separate test partial adds six independent synthetic controls, using the
  existing checksum, frame, PCAP and nonuniform-time builders. Existing parser
  fixtures remain intact.
