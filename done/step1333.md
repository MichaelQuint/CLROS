# Step1333: Minimal API builder evidence admission

## Change and purpose

Integration #737 owns the sockets/epoll and M10 application-start batch. This
first implementation slice strengthens #214/#215's existing three-application
Linux publisher without changing the app or adding an alternative publication
recipe. Hello, original RuntimeSmoke and MinimalApiSmoke remain the exact set.

The HTTP qualifier checks real Kestrel twice: the exact default health response
`OS_MINIMAL_API_OK`, then a distinct environment-supplied body. Each run checks
root/health/config responses and orderly termination. The publisher now rejects
missing, duplicate, reversed or contradictory finite-app markers. A successful
run seals source and output hashes, including payloads, native input inventory,
logs and traces. `nativeaot payload validate <evidence-directory>` rechecks those
bytes against the original source and native dependency files. The parser alone
grants no execution authority. Historical receipts remain historical evidence;
this new validator requires its own versioned receipt.
