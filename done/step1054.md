## Failures

Two early focused builds failed because BootSequence referenced the new core
before it was integrated; their logs are preserved. The combined focused run
above passes after integration. A synthetic RWX fixture in the leaf correctly
failed TypeManager registration; its control was corrected to mutate the image
after valid registration and verify rejection. Review found a missing sealed
table extent and fixed it before the final eight-group core run. Review also
replaced unavailable no-stdlib `ushort.MaxValue` with identical `0xFFFFUL`.

No new full acceptance run has failed or passed. All three aggregate fixture
pins now match the independently derived 129 raw inputs and the exact
development guest publication. The source-contract diagnostic still precedes
the full gate. The first native
publication `13f8127f1a194a47a80e7d64d7f44b75` compiled and linked but its verifier
rejected a legitimate RW cell section: an unsuffixed high-bit PowerShell hex
mask was a negative Int32. Using the explicit Int64 mask fixes that comparison.
The failed attempt and original zero-extent probe are retained as history.

Native review disproved the provisional assumption that all three receiver
classes had sealed tables. Only the base owns one; A/B use four virtual slots.
The corrected guest/parser bind the actual table and cell contribution lengths,
declaring owners and generic interface slot 1. A parser comparison between
separate phases' minimum stack addresses was removed: compiler frame size does
not strengthen stack authority. Each phase still checks the original bounds
and canaries, and dispatch's own minimum remains monotonic. A valid differing
frame-depth control guards this regression.
