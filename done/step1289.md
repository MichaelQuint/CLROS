# Step 1289 - Real coarse monotonic time for NativeAOT waits

## Why

Original-runtime r15 emits its managed EH-success row, then reports
`thread_start_timeout`. Actual parent/child syscall228 requests use clock6 and
receive EINVAL. The pinned [minipal low-resolution clock](https://github.com/dotnet/dotnet/blob/820230c386db5b0106c5430b3e5aee92a7826bf5/src/runtime/src/native/minipal/time.c#L100)
uses CLOCK_MONOTONIC_COARSE on this Linux build, asserts success, then consumes
the timespec. A release build has no fallback from an unsupported clock6.
The rejected request leaves its output unfilled; runtime tick/deadline decisions
therefore cannot be trusted. Supporting the measured clock is required before
diagnosing the remaining real application waits.

## What changed

`LinuxStartupServices.Clock` admits CLOCK_MONOTONIC_COARSE(6) alongside
CLOCK_MONOTONIC(1), reading the same genuine monotonic source/epoch and rounding
coarse nanoseconds down to a declared1ms resolution. Invalid IDs, output ranges,
source regressions, source failure and copy failure retain existing rejection.
No UTC/realtime source, elapsed-time fabrication, app change or timeout extension
is added. sched_yield remains explicitly unsupported pending actual scheduling.

## Files changed

- `LinuxStartupServices.cs`: measured clock ID and finite coarse resolution.
- Its existing host fixture: real x64 timespec values, ordinary/coarse epoch,
  second rollover, unsupported IDs and unchanged output on rejected paths.
- `EfiContracts.Sources.cs`: reviewed normalized startup-service identity.
