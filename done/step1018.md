# Step 1018 - Materialize retained memory for the real-exit path

## Summary

Add one bounded owned-data arena for #64: disjoint coordinator/binding/native
contexts, owned GDT/TSS/final and bridge IDTs, a 64-KiB final-map buffer, 256 KiB
of main-stack pages, and three 16-KiB IST stack regions. Initialize all storage,
reuse the existing GDT/IDT encoders and descriptor-bridge preparer, and place
eight checked canaries. Reserve eight guard pages in the layout for the eventual
owned hierarchy to omit. Materialization does not change page mappings.

The native stack entry now rejects IF=0 before calling the adapter. It preserves
enabled interrupts and the firmware page-table registers through the call.

## Why

The terminal helpers need actual retained storage before the final firmware
window. A fixed 105-page data layout bounds initialization and leaves explicit
regions for descriptors, map growth and guarded stacks. The x64 UEFI environment
requires at least 128 KiB of available stack and enabled interrupts; the main
stack region leaves that minimum plus over 64 KiB for the first-party path after
canaries and the entry call frame. Actual native call-depth and remaining firmware
headroom must still be reviewed at the integrated call sites.

## Deferred work

The supplied vector page must already contain authenticated owned terminal
handlers. Preparation writes descriptor pointers but does not authenticate handler
code, prove ownership/page permissions, remove guards from page tables, allocate
firmware pages, load descriptors or switch stacks. One original exclusive state
and stable caller-owned writable storage remain required. No unwind support is
introduced. Guard reservations are not proof of guarded live stacks.

Complete actual sparse owned mappings, terminal fault/COM1 paths, firmware table
provenance, full native/firmware stack review, default-off EFI wiring and live
negative/QEMU acceptance before merging PR554 or closing #64. Canonical boot/EFI
and compatibility docs await integration-lane release and must be reconciled
before merge. No real ExitBootServices, hosted .NET, Kestrel, cloud or production
claim follows from this preparation.
