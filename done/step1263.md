# Step 1263 - Drain dynamic user memory and scrub the initial ABI stack

## Summary

The default-off M16-008/009 native owner now clears dynamic user mappings and
their backing after every process/thread/borrow and descriptor has drained.
It binds the initial ABI stack to the audited static mapping, zeroes it and
reads it back before emitting terminal ownership witnesses. Thirty-one focused
checks and the combined no-stdlib C# compile pass. No native publication, QEMU
run or unfiltered full-host suite is performed for this step.

## Why

The existing process release reclaimed thread metadata and the cooperative
pool, but left anonymous/brk reservations, dynamic backing and initial stack
bytes live. Root restoration alone therefore could not establish terminal
user-memory cleanup for #687. Reuse the existing audited atomic Unmap path
instead of introducing another allocator or memory-release API. The prerequisite
was claimed in #733 before editing; keep the same eight-issue batch.

## Files changed

- `src/OS/Boot/EfiEntry.LinuxThreadRun.cs`: after release and descriptor closure,
  require syscall/memory phases, detached mutation guard and audited memory;
  read actual CR3 and require the kernel root active/user root inactive; bind
  pool and initial-stack pointers to their audited owned ranges. Unmap the full
  4..64-GiB dynamic window, require zero reservation/backing counters, audit and
  refresh the retained root, then zero/check the initial stack and check every
  pool byte. Any failure withholds the terminal witness. The existing owner-end
  row records actual `userReserved`/`userBacked` values and `initialStack=zero`.
- `tools/OS.Tooling/QemuTranscripts.LinuxThreads.cs`, `.LinuxSignals.cs` and
  `.LinuxSignalIrqs.cs`: require the complete new owner-end suffix, including
  both zero counters and the initial-stack witness. No new row or input byte.
- `tests/OS.HostTests/LinuxMemoryServicesTests.cs`: full-window unmap over
  backed, PROT_NONE, sparse/high and read-only dynamic ranges. A retained borrow
  denies mutation and guard detachment without changing counters/tables/bytes;
  after borrow release, unmap scrubs backing, removes dynamic leaves and keeps
  static code mappings. Empty repeated unmap remains valid.
- `M16008EfiIntegrationTests.cs` checks the cleanup boundary and root/static
  stack admission; the three corresponding transcript fixtures add missing,
  nonzero-counter and dirty-stack rejection controls. The fault-tail fixture
  consumes the same updated owner-end generator.
- Canonical `docs/app-model.md`, `docs/diagnostics.md`, `docs/qemu.md` and
  `docs/efi-build.md` describe the revised protocol and retained allocations.

## Evidence

Final `EfiEntry.LinuxThreadRun.cs` raw SHA256:
`667EABB409862A8AEA4E877E2F631CFE8764371B658CD56E25298722F0CE0128`.
The runtime computes and checks actual counters, mappings, CR3 and bytes before
its witness. Host controls test existing memory mutation/scrub behavior and the
strict parser; they do not execute this EFI cleanup function.

Static image and initial-stack mappings, owned physical/table allocations and
firmware reservations are retained. Only dynamic reservation/backing ownership
is relinquished to the existing owned pool; initial-stack bytes are scrubbed.
Mechanical fixtures may use stacks in their ELF data, so `initialStack` does
not assert that every static ELF data byte is zero. Step1259's one diagnostic
remains historical evidence for its exact source, without these new witnesses.
