# Step 1315 - Persistent TCP receive-window development

## Summary

Implement #150's receive-window consumer within the existing #734 network/TCP

## Why

The original ref-struct stream is a strict caller-stack helper. A live receive
path needs persistent generation-bound buffer ownership, partial-window/overlap
handling and cumulative ACK progress independent of TX capacity. Reuse that
helper's packet/buffer/checksum logic while preventing duplicate delivery or
premature table/buffer release. Preserve the original strict APIs for existing
consumers; the actual receiver uses the explicit windowed path.

## Files changed

- `src/OS.Kernel/Net/TcpReceiveWindow.cs`: one zeroed caller-retained owner binds
  an established table handle and 1..32768 private bytes. The initial advertised
  window must match capacity and IP endpoints must match the table. Persist
  scalar offsets/counts and pointers; borrow a temporary ref-struct view per call.
  Reject copied/stale/foreign identities, aliases and unsupported frames before
  writes. Receive validates original Ethernet/IP/TCP identity/checksum, accepts
  only the contiguous unseen portion, trims old overlap/window excess and drops
  gaps without a queue. Duplicates/gaps/full-window probes schedule current ACK;
  an acceptable empty ACK returns NoPayload without starting an ACK loop. Receive
  does not send: drain a bounded RX batch, then PumpAck serializes one latest
  cumulative ACK/window. Only accepted copied TX clears the pending flag; full
  or short output retains it, fatal TX retains explicit cleanup. Read copies
  bytes once, scrubs consumed storage and schedules a window update. After the
  close consumer marks the exact table lifetime Closed, ReleaseClosed scrubs the
  whole private buffer, explicitly discards unread data, detaches and retires.
- `src/OS.Kernel/Net/TcpConnectionTable.cs`: add one internal receive-owner
  address to each entry. Reject duplicate receiver binding, preserve attachment
  across owned state/send-sequence updates and prevent unauthorized receive-
  sequence changes. Closed table release returns AttachmentsRemain until the
  receiver detaches. Legacy span mutations/reuse reject attached entries. Owned
  entry storage remains exclusive; do not mix legacy mutation APIs with an owned
  lifetime. This changes internal unmanaged entry layout; native qualification
  remains outstanding. No new socket handle or hardware authority is created.
- `src/OS.Kernel/Net/TcpEstablishedStream.cs`: explicit ReceiveWindowSegment
  shares the original parser, flags, ports, ACK validation and copying. Trim old
  prefix/window excess and apply modulo-32-bit sequence arithmetic; keep strict
  ReceiveSegment behavior for existing clients. Internal restore/offset helpers
  borrow only already-validated persistent storage, without retaining a Span.
- `src/OS.Kernel/Net/TcpEstablishedStreamIpv4FramePlanner.cs`: share original
  frame/identity/checksum validation between strict/windowed receives; add pure
  ACK serialization with the current free window and no sequence advancement.
- `tests/OS.HostTests/TcpReceiveWindowTests.cs`: thirteen cases use independent
  Ethernet/IP/TCP bytes and checksum arithmetic. Cover in-order delivery and ACK
  aggregation, overlap/window clipping, gaps, zero-window probes/reopening,
  sequence wrap, full/short TX, malformed identities/checksums/flags/fragments,
  unique binding/legacy mutation guards, metadata update preservation, closed
  detach/release, copy/stale/foreign/alias/storage failures, fatal ACK cleanup,
  buffer compaction and 10,000 warmed receive/read/ACK cycles allocating no
  managed bytes. Pure ACK writer rejection/preservation has a separate case.
- `docs/networking.md` and `.gitea/backlog/clros-issues.json`: development evidence
  and limits only. Dependencies, acceptance labels and desired states are unchanged.
