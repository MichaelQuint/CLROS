# Step 1026 - Gate post-exit COM1 markers on owned-state validation

## What changed and why

`FirstExitPostExitDiagnostics.Report` consumes one image-resident report state.
It requires successful exit state, cleared firmware bindings, matching native
entry/adoption observations, exact callback/context addresses, owned stack
bounds and actual table backing at the observed CR3 address. It reconstructs
the retained layout and checks installed descriptors/code before any output.

Only the checked owned COM1 backend is accepted. After configuration, output is
`M03_EBS_RETURNED_SUCCESS`, then an audit of the actual retained table image,
then `M03_PERMANENT_CR3_ADOPTED`, another canary check, and finally
`M03_POST_EBS_OWNED_DIAGNOSTIC`. Each line includes CRLF. Every byte has at most
128 transmit-ready polls. Failure consumes the attempt and suppresses later
markers; the caller must halt after every return, including success.

Fresh descriptor checks remain strict. Separate installed checks require native
GDTR/IDTR/TR/segment observations, the busy TSS and unchanged descriptor content,
allowing only code/data accessed flags. The rules follow the
[Intel SDM, Volume 3A](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-3a-part-1-manual.pdf).
Installed range/code validation reuses the original checks. Bounded caller-owned
scratch may now reside within the main stack, excluding its canaries/guards;
other input/output aliases remain rejected.

## Failures and limits

guessed filenames; file discovery located the existing implementations.

This is a callable post-exit implementation, not live EBS/CR3 proof. Supplied
observations and original pointer/lifetime declarations still require an
authenticated adapter. Tests invoke no privileged instruction or real port I/O.
The reporter does not itself halt; the existing terminal native callback path
must enforce that rule. Code publication, default-off EFI wiring, complete native
callback/IST stack review and fresh QEMU acceptance remain required before #64
or PR554 can complete. Reconcile canonical boot/EFI docs before merge after #552
