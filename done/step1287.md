# Step 1287 - Runtime futex backing and retained mapping capacity

## What changed and why

The failed original RuntimeSmoke r13 guest exposed two production-service
admission defects. Attaching descriptors made every user backing page a
forbidden futex alias. Separately, 53 retained mappings left only11 rows in a
64-row combined inventory; the original startup trace exhausted those rows
while ample physical pages and page-table pages remained.

`ForbiddenFutexAlias` now excludes descriptor metadata while allowing validated
application backing. Only that caller opts out of the full backing-pool
exclusion; service metadata admission retains it. Resolver/PTE, generation,
ownership, pending/woken wait and memory-mutation checks are unchanged.

The combined user-root construction inventory increases from64 to128 rows.
Memory-service static admission remains fewer than64 rows and mutable-region
capacity remains64. The existing4096 physical-page and128 table-page quotas,
virtual reservation limits and ownership checks remain unchanged. Native
stack/resource implications still require review.
