# Step 1509 - Own web-race reports through a bounded runner rendezvous

## What changed and why

The ordinary runner terminates QEMU after its web controls. Add an explicit,
default-off same-user named-pipe handoff there so an owner can finish the observed
race producer before termination. Strict fresh pipe names, canonical bounded
ASCII CRLF READY/DONE frames, one connection and ordered phases reject malformed
or repeated handoffs. Runner I/O monitors actual QEMU/frame/serial health at
50ms intervals, requires35s remaining before entry and clamps its maximum45s wait
to the original absolute deadline. The285s web cap is unchanged. Validation and
dry-run open no IPC. Only explicit mode adds race summary rows; ordinary HTTP,
UTC, packets and summary contracts remain unchanged.

The new Tooling owner starts the bounded runner callback, waits for READY after
ordinary controls, owns the actual observed HTTP task and joins its streams and
report persistence. Selected/attempt/wire creation handles retain identities,
single-link counts, lengths and exact flushed-byte hashes. Read-only bridges
keep those identities alive across writer closure until immutable held opens
match them. The returned selected JSON also matches original bytes. Run strict
logical/wire/HTTP inspectors before sending DONE with the three held hashes.
Keep originals and pipe alive through the runner join. A private Completion
requires complete successful process/death flags, matching gate/PID/digests and
held originals/logs. These component checks do not replace the full guest reader.

All failure paths close the rendezvous, cancel and join started tasks, retain
exact available runner stdout/stderr plus partial HTTP reports, preserve the
primary error and refuse unconfirmed termination. The330s aggregate owner bound
does not extend the runner deadline. Its callback must use bounded ProcessRunner,
honor cancellation and confirm termination; copied callback/PID values confer no
native, serial, packet or guest authority.
