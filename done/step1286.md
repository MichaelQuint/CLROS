# Step 1286 - Native runtime qualification and user-root pool permissions

## Summary

Starts actual native/QEMU qualification of the eight-issue thread/runtime batch.
Repairs missing reviewed symbols, user-root thread-pool permissions and the
active TSS-borrow admission boundary. Qualification remains in progress.

## Why

The independent user root copied the entire retained thread pool as supervisor
RW/NX before kernel publication. Publishing kernel RX leaves did not alter
that root; every mmap also rebuilt the stale declaration. The E1 entry executes
before switching CR3 and therefore faulted on its first instruction.

- `EfiContracts.Admission` and runtime integration controls: complete reviewed
  define-symbol coverage for all diagnostic probes and exact new runtime symbols.
- `LinuxThreadProgram.TrySupervisorMapping`: pure bounded descriptions of RX
  code, RW/NX usable metadata/stacks and absent guards in the existing layout.
- `EfiEntry.BuildLinuxUserRanges`: retain those 21 pool spans in the independent
  user root, including every later memory-service reconstruction. Kernel-root
  staging/publication/restoration remains owned by its existing path.

  expected RSP0/IST4 validation retains original GDT/IDT/other-TSS/code checks,
  never rewrites live descriptors and preserves strict ordinary restoration.
  Pool walking authenticates each active gateway/timer borrow and NULL selector

  only in the copied continuation, retain raw capture bytes and reject ordinary
  RF returns and all other forbidden flags. Debug-resume semantics remain
  unsupported. Failure-only capture diagnostics end in a parseable failure.
