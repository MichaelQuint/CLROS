# Step 1237 - Scheduler-backed Linux futex consumer

## Summary

Development stage for #191/#686/#733, parent
`b83cad57e7709ceaa2642b0aba41fd1cb3ec9203`, draft PR #732. LAN repository ID 9
and all four current claims were refreshed. The exact new futex partial and
focused test paths were added to #733 and read back before editing. This step
was reserved using compiled OS.Tooling. No acceptance/closure intent advanced.

LinuxThreadServices now implements explicit optional futex WAIT/WAKE and
WAIT_BITSET/WAKE_BITSET admission over its existing KernelThreadTable and
WaitAddress owner. Compare/enroll creates a genuine table wait; Blocked requests
full CPL3 restoration before a real kernel CALL capture/Park. Completion is
consumed only by that actual scheduled worker. Wake returns zero, deadline
returns ETIMEDOUT, and shutdown cancellation drains as thread exit rather than
inventing a signal/EINTR. Clear-TID exit attempts the shared-key wake even when
its best-effort write faults. No second scheduler, allocation or polling is added.

## Why

Private and shared-anonymous keys must remain distinct for the same process
word. WaitAddress gains optional tagged bindings and nonzero 32-bit bitset
matching, preserving default tag zero/all-bit behavior and FIFO among matches.
Linux cells hold an exact user address, kernel alias, mapping lifetime and key
mode. A stale resolver result fails closed rather than waking another backing.
Completed waits retain references until completion consumption or exit; the
memory-owner guard returns false for overlapping mutations until references
drain. The native memory owner still must actually consult that guard.

Relative WAIT and absolute monotonic WAIT_BITSET use the kernel table's selected
nanosecond epoch and a genuine-clock callback capability. Timespec validation,
saturating Linux ktime bounds, compare-before-expired-deadline behavior and the
legacy zero/negative int wake-count behavior are explicit. Realtime, PI,
requeue, robust-list success, file/shared-memory mappings, user-VA aliases and
signal delivery remain unsupported. Callbacks/lifetime declarations and host
clock simulation do not establish native behavior.
