## Implemented behavior

The adapter revalidates retained MCFG checksums, reserved fields and allocation
ranges, rejects overlapping physical or bus authority, and admits one allocation's
first bus against the original owned EFI map and all later owned allocations.
MCFG base remains relative to bus zero, even for a nonzero start bus, per the
[PCI host-bridge authority documentation](https://kernel.org/doc/html/v5.19/PCI/acpi-info.html).
No reference implementation was copied.

One authenticated 16-byte native leaf performs an aligned DWORD read. There are
no configuration writes. The guest aperture is one read-only/NX uncached MiB
(256 function pages); host contracts accept up to four buses below 4 GiB.
A live session has one exclusive mutable owner and is revoked before success;
copying the struct does not create an independently revocable capability.

The scan checks function zero before optional multifunction siblings, validates
bridge bus ranges, records the last visited tuple and distinguishes output
capacity from read-budget exhaustion. Completeness applies to the requested
window only; absence within an entire allocation additionally requires full
allocation coverage and no unscanned bridge. The guest checks repeated scans and
one-record truncation. Conventional capability parsing reads a stable 256-byte
snapshot with at most 48 linked headers, accepting unknown IDs and rejecting
cyclic, unaligned or out-of-range links. Payload/extended capability semantics
remain separate work.
