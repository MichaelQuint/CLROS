Thread-enabled gateway dispatch now routes every fd operation through the
LinuxThreadServices descriptor owner, preserving its reference/wake transaction.
One gate belongs to each actual worker generation. A blocked gate retains the
original call, refuses another dispatch and accepts actual completion without
replaying or recounting it. Repeated capacity waits retain the same call. Only
the final successful write prefix contributes to its per-gate byte counter.

LinuxThreadProgram emits up to four cooperative kernel workers around the
separately owned CPL3 gateway, reusing KernelThreadEntry/ThreadContextSwitch.
Its fixed CALL continuations permit actual kernel capture only after full
gateway restoration. The native EFI owner and M16-008 profile remain unlinked.

## Why

The old immediate long-valued descriptor callback cannot express a staged pipe
wait. The explicit threaded result now preserves Blocked/Return/Exit ownership.
Completion checks original read/write bounds and the current user return
mapping; malformed results terminate the gate without false byte accounting.
Shutdown exits need no unused user return target. Thread exit consumes only its
own gate; process shutdown still belongs to the native process owner. The legacy
non-thread descriptor path retains its behavior.

The worker emitter has distinct supervisor drivers, entry adapters and bidirectional
switch stubs. Prepare either installs a checked saved user image or stages an
actual wait/exit; it cannot invent completion. Each gateway return is followed
by the real FromWorker CALL. Recovery restores the freshly admitted supervisor;
timer code remains separately owned. All byte emission is unpublished and dry
validated before writes. Fixed stack minima are 168 bytes at initial entry and
80 below captured RSP; actual callback/native stack budgets remain a separate
qualification obligation. No scheduler, user IRQ frame, allocation or foreign
native implementation is introduced.

literal needed UL and the witness negative needed the descriptor's Context
pointer. Fixed before execution. M09009 compile r01 exposed the new CS0649
ThreadOwner warning; explicit zero initialization fixes it in r02.

padding after SUB RSP and after the gateway CALL. Independent source review
found both; explicit jumps now skip the padding, with independent target
assertions. Review also found that the generic entry adapter's lower-stack
minimum was insufficient for this worker/gateway chain. Initial 168-byte and
captured 80-byte fixed-frame guards now reject low+72/low+32 controls. Final
emitter r03 includes both fixes. Earlier passing byte checks are not evidence
that those defective paths could execute. Failed/earlier logs are preserved;
no native/guest run was attempted.
