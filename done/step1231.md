# Step 1231 - Host wait-address registrations

## What and why

Implements the first host stage of M09-009/#191 on accepted master
`948d7b0d43183e5880aa933d2bdaf8cef924ef5a`, alongside claimed #192 on
`codex/m09-wait-address-tls`. Both claims and comments were read back on the
canonical LAN repository; no other live claim existed when ownership began.

`WaitAddress` uses caller-owned fixed slots and registration buffers over the
qualified `KernelThreadTable`. Exact address/lifetime bindings, owner keys and
nonwrapping generations reject stale aliases. Aligned four-byte comparison and
wait registration precede the caller's capture/Park/transfer in one IRQ-off BSP
transaction. Wake-before-park is retained by the lifecycle table. FIFO wake-one/
all preserves a winner under full ready capacity; timed registrations use the
existing deadline queue. Sweep removes only completed/stale references, and
Unbind refuses a live waiter. Storage/word ownership never transfers implicitly.

The implementation performs no hardware operation, native transfer, hidden
allocation, polling, Linux errno translation or application runtime work.
