# Step 1337 - Bounded Linux socket/TCP owner development slice

## Summary

Implement the measured passive IPv4 socket operations for #689 under integration
#737, sharing the existing Linux fd/open-description namespace. This is host-tested
development, not issue acceptance. All current batch issues remain open.

## Why

Step1336's real pinned Linux socket fixture measured accept4, sendto/recvfrom,
fcntl, socket options and shutdown. Reuse the accepted TCP transport owners
instead of introducing another socket buffer, descriptor table or fake transport.

## Files changed

- `LinuxSocketServices.cs`: bounded owner/endpoint admission, exact manifest bind
  capability, create/listen/accept, address/options, nonblocking partial I/O and
  explicit closed reap. Genuine upstream TCP-window/table ownership is retained.
- `LinuxDescriptorServices.cs`: shared socket descriptions, dup/status flags,
  ioctl, read/write/writev and last-close integration. Descriptor End cannot
  complete while fd-less TCP ownership remains retained.
- `LinuxSyscallGateway.cs`, `LinuxThreadServices.cs` and
  `LinuxThreadServices.Pipes.cs`: route measured calls through the current worker
  and include socket metadata in descriptor attachment nonaliasing checks.
- `LinuxSocketServicesTests.cs`, `LinuxSyscallGatewayTests.cs` and
  `docs/networking.md`: behavior, routing, feature-boundary and status evidence.

The socket references use `CLROS_LINUX_SOCKETS` in no-stdlib EFI builds. Older
descriptor/threading profiles do not acquire the TCP source dependencies or the
socket-state field. The new EFI switch/profile is deliberately not wired yet.

## Evidence

Ignored evidence root: `artifacts/nativeaot-sockets-first-web-r01`.
`socket-kernel-checkpoint-r01.json` retains exact source/log hashes and counts;
individual build and focused logs retain commands/results and worker receipts.

Tests use the genuine passive-handshake, RX/TX-window and table implementations
with independently constructed packets. They prove bounded partial sends,
backpressure, copy-failed receive retention, denied/malformed endpoints, capacity,
dup/fd reuse, backlog retention, FIN/EOF, reset-error consumption and closed scrub.
The user-copy callback completes before RX consumption. A full graceful close
still allows unread final bytes to drain. Faulted reads expose no bytes.
Last close starts FIN drain; a failed transport is explicitly aborted before
the retained buffers/table generation can be reaped. No NIC is exercised here.

The frozen original `NativeAotPayload.cs` remains byte-identical, SHA256
`44F16ABB380FE7F3CD42BA3C7E54710172F0320998CF2E85E296F8A7CE184AA5`.
