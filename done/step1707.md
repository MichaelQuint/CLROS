# Step 1707 - Compiler-selected managed-heap adapter tests

## Summary

The managed-heap EFI fixture now finds the admitted adapter and callers through
the actual compiler profile, rather than extracting a region of EfiEntry.cs.
Its generated hosted adapter preserves separate declaration/import scopes.
The r74 focused Fast/Native selections pass nine checks across four groups,
including actual no-stdlib managed metadata and two 50-case hosted executions.
The final retained-validation guard refinement passes five affected Fast checks
at r76. All results have unchanged inputs and zero reuse.

## Why

Partial extraction invalidated the original filename and region assumptions.
The selected source guard retains original allocator/node fields, a stable fixed
heap slot, initialize/retain modes, rejection polarity, failure stop and later
boot-plan ordering. The hosted fixture must also survive a method moved into
another partial with a different alias scope; passing a source-only guard would
not establish that its generated program can still compile and execute.

## Files changed

- HostManagedHeapSourceGuard.cs and HostManagedHeapSourceGuardTests.cs.
- M04ManagedHeapPageRangeEfiIntegrationTests.cs: TestProject source selection,
  TestAdapter delegation to TestAdapterSource, and Sources replace the two
  textual region helpers.
- Host requirements and repository-audit documentation.

AdapterSources emits each selected active declaration in its original namespace
and import scope inside a partial hosted Program wrapper. Only the two bound
allocator calls are replaced by the existing independent failure-injection shims.
The hosted project takes its kernel/shared input files from the evaluated
profile and excludes the complete selected Span/ReadOnlySpan families, preserving
the original fixture's intentional use of framework spans.

Independent token comparison preserves thirteen other fixture methods, all
fields/order and both raw literals, including the complete 50-case program.
The generated Program namespace/partial prefix changes intentionally. Production
allocator, kernel, EFI adapter and ABI sources do not change in this step.

Positive controls cover moved types/methods, local renaming, allocator aliases
and conflicting per-part aliases. Negatives cover substituted/reset/escaped
authority, wrong checkpoint mode or slot, inverted rejection, ignored retained
result and an empty failure branch. This is bounded source checking, not an
arbitrary control-flow or pointer-alias proof. Existing mapped-buffer tests own
the expected states, return decisions and all 200 ledger bytes.
