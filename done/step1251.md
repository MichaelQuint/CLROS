## Why

The pinned runtime's activation and System.Native signal worker require real
interrupted waits. Fabricated EINTR, restarted relative timeouts and replayed
partial writes would produce incorrect lifetimes or indefinite waits.

KernelThreadTable.Interrupt reuses its existing complete/ready/deadline owner.
It authenticates generation/sequence, excludes join waits, retains the first
wake/deadline/cancel/interrupt winner and does not set thread cancellation.
Ready overflow retains Pending. Existing enum values are unchanged; Interrupted
is appended. Real-clock deadline advance precedes interrupting a futex, even
when another worker has kept the CPU out of its idle timer loop.

Tgkill queues the directed event and completes its actual unmasked wait. Masked
or ignored sends do not interrupt it. A pre-existing wake/timeout keeps its
result and the signal still reaches pending delivery. Futex completion drops
the word reference; pipe completion drops the original open description. A
positive pipe prefix is final and never rewound. Zero-progress pipe and untimed
futex interruptions stage an original-syscall restart decision; a selected
handler restarts only with SA_RESTART, while no remaining handler restarts it
unconditionally. RAX/RIP are adjusted before building the genuine user frame,
so validated handler edits still control the eventual return.

Timed WAIT/BITSET interrupts expose EINTR to handlers regardless of SA_RESTART.
An independent timed restart callback retains original arguments and absolute
deadline through handler execution/I/O until rt_sigreturn. No-handler return
selects syscall219; it consumes the callback before re-admitting the futex and
never rereads the old timeout pointer or restarts a fresh relative interval.
Retries recheck the current word/mapping; pipe restarts resolve the fd again.
rt_sigreturn invalidates the callback; absent state returns EINTR.

No internal restart errno is written to the user image. CurrentImage refuses
an unresolved interrupted return until DeliverPendingSignals resolves it.
Rewind validates mapped executable SYSCALL bytes and the adjusted return; bad
opcode/copy stages owned shutdown139. Actual native attachment must call this
decision path before installing the complete user image.
