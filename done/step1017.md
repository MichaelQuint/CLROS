# Step 1017 - Enter the final firmware-call path on an owned stack

## Summary

Add a C# emitter and bounded preparation for the owned-stack entry required by
#64. The entry checks its original prepared context, firmware CR3/CR4, stack
canaries, alignment and callback before consuming the context. It switches RSP
to the owned stack and calls the final-call adapter with the original context.
Every explicit refusal and unexpected callback return reaches CLI/HLT forever.
There is no return or restoration of the caller's firmware stack.

## Why

The final memory-map/ExitBootServices coordinator and permanent-CR3 continuation
must already execute on a retained stack. The new entry preserves firmware CR3,
CR4 and interrupt-enable state through the callback, so it can issue its final
firmware calls under the original environment. Returning to ordinary firmware
work after an issued exit is forbidden even on failure; the terminal fallback
therefore applies to every callback return.

## Deferred work

These checks compile and decode the native path; they do not execute privileged
instructions or prove live stack switching. The adapter must supply an original
exclusive context, authenticated entry, valid mappings for both stacks and every
reachable code/data range, initialized canaries and a reviewed full call-path
budget including firmware. No exception/unwind support is introduced. Entry's
callback must consume the firmware binding and invoke the terminal coordinator;
only successful EBS permits the existing permanent-CR3 continuation.

Actual arena/handler/mapping preparation, default-off EFI wiring, owned COM1,
live negative controls and native/QEMU acceptance remain required. #64 remains
open/claimed and PR554 draft. #552's separate original run at clean3665029 continues
without source/binary changes. No duplicate complete suite or QEMU run was started
