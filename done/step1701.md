# Step 1701 - Resolve managed tools from their selected build graph

## Summary

The host runner and tooling launcher share compiler-bound project-output
discovery. Managed tool paths no longer assume bin/configuration/net11.0 or an
assembly filename matching its project. Self-only producers are valid. Eight
focused checks pass at r58; the preserved r57 complete fast diagnostic still
fails in 56 fixture groups.

## Why

Step1697 removed the test runner's output-path guesses, but HostTools.ManagedTool
still reconstructed those paths. Native process owners also use that launcher,
including launching OS.Tooling itself from a loaded host-test copy. Discovery
must preserve the comparison between that copy and the selected original target.

## Files changed

HostProjectOutputs and its Output record move into OS.Tooling, retaining the
parser, path/reparse checks, hash checks and directory snapshots. Resource reads
take an explicit producer assembly. HostToolProcess and HostTestFingerprint use
the host-test graph; HostTools uses the tooling graph. The hash implementation
is unchanged apart from removing its dependency on the host checkpoint class.

The shared target moves to OS.CompilerReceipts and is explicitly imported after
SDK targets in only the two managed consumers. It retains SDK-selected reference
contexts, BuildReference filtering, ReferenceOutputAssembly=false dependencies,
recursive diamonds and ambiguity rejection. An import flag prevents duplicate
query-injected and direct imports. EFI/root build imports are unchanged.

A separate self descriptor records project, selected TargetPath and context,
avoiding a cyclic embedded self hash. Self resolution checks that target against
the loaded producer file hash. Missing, changed, escaping or linked inputs and
self/child identity collisions reject; there is no guessed-path fallback.
Existing native producer leases and cleanup ownership remain unchanged.

An authenticated header-only child map now represents a producer with no child
projects. Missing or malformed resources still reject, and an absent child name
cannot resolve. Child count is discovered, not required to exceed zero.
