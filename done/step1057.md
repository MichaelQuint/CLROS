# Step 1057 - Original-image unwind metadata development integration

## Summary

Issue #574 integrates the reviewed #89 metadata core from step1055 with the
original TypeManager registration and M01 stack. The default-off child invokes
two real compiled methods, looks up their entry/last in-range PCs, and checks
two expected misses. A development native publication and the original QEMU
wrapper pass. This is not frozen-commit acceptance or completion of #89/#574.

## Why

Host parser fixtures cannot demonstrate consumption of the actual NativeAOT
image. The child retains the original capture, mapping, module storage, handle
and section-204 slot, snapshots bounded metadata in one private static buffer,
and associates observed PCs with the current image's runtime-function table.
It adds neither a second registration nor an ordinary boot phase.
