# Step 1322 - Keep the continuing-network clock helper disjoint from PCI and queue code

## Summary

The first M07-026 native candidate publishes/verifies, but its first real guest
stops before firmware exit at preparation60. The combined profile emits clock,
PCI read, BAR and queue-fence bytes over the same code slots. Move only this
profile's clock helper to an unused aligned slot; retain every accepted profile's
existing offsets. No TCP execution or batch acceptance is claimed here.

## Why

The managed compile and prior host tests had not materialized the exact combined
native helper layout. This is a concrete integration defect exposed by the first
guest, before the new networking path can run.

## Files changed

- `FirstOptRealExitBootServicesTransition.cs`: `ClockAccessOffset=5600` only when
  M07-026 selects the clock; otherwise retain4608. No new arena, code allocation,
  callback or layout framework. The 96-byte helper stays below stack entry8192;
  all emit/validation/padding/adapter uses derive the existing constant.
- `M07026EfiIntegrationTests.cs`: preprocess the actual thirteen-flag no-stdlib
  profile, check clock/PCI/BAR/fence ranges, then emit and read back all four
  original helpers together. Existing source identity and networking status doc.
