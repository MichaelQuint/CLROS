## Summary

Independent image/log joins account for all 145 physical requests and 241 sectors
in each of six retained diagnostic boots: 113 metadata requests and 32 four-sector
payload requests. No storage algorithm, cache, budget or error precedence changes.
This narrows the performance investigation without claiming a measured speedup.

## Tests run

The probe authenticates the retained image/receipt, classifies every requested
sector, and joins path rows to unique syscall identity/ordinal, blocked wait
sequence and completion. Six nonoverlapping intervals account for all metadata;
the residual requests contain only the requested CoreLib range. Every boot gives
the following same work:

| Role | Requests | Sectors |
| --- | ---: | ---: |
| Directory contents | 47 | 47 |
| Target file-chain FAT pages, both mirrors | 62 | 62 |
| Directory-chain FAT page, both mirrors, loaded twice | 4 | 4 |
| Payload | 32 | 128 |

The first stat with a trailing slash returns ENOTDIR after 76 requests; the next
lstat uses 9; a second trailing-slash stat, two more lstats and open each use 7.
The asset is 2,009,369 bytes, but this capture transfers only 65,536 bytes.

The image has twelve relevant directory sectors. With five reusable sector
slots and the existing complete-scan contract, six lookups require at least
12 + 5*(12-5) = 47 directory reads. The current cache attains that bound. Finding
the requested entry early does not prove absence of a later collision, malformed
VFAT sequence or traversal-budget failure.

There is one physical full-file-chain read set. Moving ENOTDIR ahead of chain
validation predicts request counts [14,69,9,7,7,7] instead of [76,9,7,7,7,7]:
still 113 metadata requests. This is a source/cache prediction, not an executed
alternative. It also changes precedence against malformed-chain, mirror and I/O
failures, so it is not a mechanical cleanup.

Current Chain.Visit source checks prior history elements on every append. A
cold 3,925-cluster validation implies 7,700,850 prior-entry checks. This is a
source-derived work count, not measured CPU time. Existing file certificates
retain map/metadata/epoch authority, but no durable exact-path witness; reused
operation buffers cannot safely serve as a namespace cache.

Source review compares 22 selected methods in three relevant contexts (66 token
pairs), retained source853ea7ed versus captured current storage/caller files.
No repository build, native publication or VM was run for this analysis; existing
host/full results are not relabeled as tests of a proposed optimization.
