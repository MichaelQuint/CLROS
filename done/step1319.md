# Step 1319 - Retained TCP termination and half-close development

## Summary

Compose #153 termination into the existing unique sender/receiver in #734.
Seventeen new termination cases join 274 passing TCP fast checks across 30
fixtures. This is host development; native/full/guest/packet acceptance remains.

## Why

Nominal close-codec states do not own real retained send/receive bytes. Keep FIN
sequence and retries in the actual sender, consume EOF from original receive
frames, and retain the exact table generation until explicit terminal cleanup.
No second connection/buffer controller or broad TCP framework is introduced.

## Files changed

- `TcpSendWindow.Close.cs`: partial implementation over the existing unique
  owner. Explicit close configuration, queued-data-draining ShutdownWrite,
  original frame/ACK/FIN/RST dispatch, copied-TX-only FIN, bounded close budget,
  simultaneous close and monotonic TIME-WAIT/restart. Default/minimum TIME-WAIT
  is 240 seconds (RFC9293's two-minute MSL, doubled). It supersedes shorter
  workload/close deadlines; an unrepresentable deadline faults with ownership
  retained, never saturates into early success. Exact RST closes; in-window
  nonexact RST requests a challenge ACK; TIME-WAIT ignores RST. Abort is explicit
  after send/clock/timeout failure, emits no fabricated RST, and releases nothing.
- `TcpSendWindow.cs`: FIN uses the existing RTO/copy/attempt mechanism and one
  sequence without releasing a fictitious buffer byte. ACK restarts/disarms
  progress; queued writes are rejected only after local shutdown. Closed/faulted
  cleanup retains FIN/data accounting and permits either attachment release order.
- `TcpReceiveWindow.cs`: FIN consumes sequence once only after all original
  contiguous payload fits the advertised window. Preserve unread bytes/EOF after
  graceful table closure; reset/abort suppresses reads until scrub. Duplicate FIN
  only requests the current ACK. Window trimming positions FIN after the original
  wire extent, not the delivered subset. Each released buffer is checked raw.
- `TcpEstablishedStream.cs` and `TcpEstablishedStreamIpv4FramePlanner.cs`:
  internal FIN-aware original-frame path and shared control serializer; public
  strict codec paths retain their defaults. Old ACKs admitted by the retained
  dispatcher release no bytes but may carry new contiguous data/FIN. Original
  checksum/endpoint validation remains before receive progress.
- `TcpConnectionTerminationTests.cs`: 17 original-wire/owner controls cover both
  close directions, unread half-close data, window trimming/overlap, duplicates,
  FIN/TX loss/pressure/fatal errors, reset/challenge ACK, clock/timeout/overflow,
  both sequence wraps, old ACK plus new data, both cleanup orders and a fresh
  real host handshake reusing the table slot while rejecting old handle/wire FIN.
  A warmed duplicate-FIN/copied-ACK cycle allocates no managed bytes.
- Existing networking doc and M07-018 evidence only. Dependencies/labels/open
  state stay unchanged. No EFI admission/profile or guest adapter edits occur.
