## What changed and why

Correct the diagnostic defect found in step1505 without changing the app or
retrying its failed native attempt. Cleanup6 and Failed8 can legitimately retain
unknown roles. Their copied status now parses before the controller rejects
the missed recovery gate; acknowledged/success phases still require known,
nonaliasing roles. No EINTR, callback, recovery or completion criterion is relaxed.

Retain a fresh `.attempts.json` companion alongside the unchanged selected v1
report. Every owned logical HTTP call records method/path, invocation ID,
completion ordinal, received headers/status/media type, bounded raw bytes,
EOF completeness and terminal response/cancellation/fault. Selected responses
link their exact logical call; churn cancellation is a host event linked to the
original pending call. Rejected and unselected polls are retained too. All
started requests join before either report is written, without the canceled
caller token. A second join failure no longer hides the primary failure.
Receipt of response headers ends pending overlap even when its body stalls.

The copied inspector checks exact shapes, canonical bounded bodies, terminal
outcomes, unique IDs/completions, serial logical ordering, selected links and
the actual polling windows. Complete success additionally requires the original
19-row semantic contract, exactly the planned cancellation, no faults or extra
POSTs, and the final selected request as the last invocation. Failed diagnostic
ledgers remain inspectable without being promoted. The1024-call/4096-byte bounds
fit the8MiB companion limit. These IDs describe API invocations, not actual wire
connections, exchanges or sent bytes.

New explicit `nativeaot web qualify --signal-race` receipts use v6 and require
the companion under the sealed output inventory. Default v4 and historical v5
validation retain their original branches. No source/ELF/index admission changes.
