# Step 1117 - Keep host build identities stable during fixture execution

## Summary

Fixed two causes of false stale-input failures while qualifying issue #600 on
the compiled runner. Pointer and finally subprocess fixtures no longer rebuild shared
dependencies, and the embedded manifest captures generated assembly metadata
after SDK generation.

## Why

A full run started after commit 1c7950f. The two pointer fixtures rebuilt
`OS.Kernel.dll` and `OS.Std.NoRuntime.Shared.dll` in place, changing their
informational version from source revision 9a38504 to 1c7950f. The harness retained
its original dependency copies, while its manifest correctly rejected the
changed project outputs. This broke the nested resume control.

The next single build after commit ba8521f exposed a separate ordering error:
the manifest hashed the previous generated `OS.HostTests.AssemblyInfo.cs`
before the SDK regenerated it. The capture target now explicitly depends on
global-using, target-framework-attribute and assembly-info generation.

A scan of the remaining subprocess builds found the same shared-output exposure
in the finally admission guard. That build now uses `--no-dependencies` too.
