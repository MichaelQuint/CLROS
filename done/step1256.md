## Why

The new packages contain genuine CPL3 fault instructions, not synthetic fault
callbacks: a moffs64 read at0x150000000, a write to RX text, a jump to NX data,
the high read with actual user RSP0, and CLI. The read target is above the entire
retained physical identity range and below the64-GiB user end; it is outside the
native owner's heap reservation at0x400000000/2MiB. This avoids assuming a low
address cannot overlap a supervisor identity mapping.

Each recovery handler verifies every saved64-bit GPR, original RAX, RIP/RSP,
trap/error/address, RF/DF, x87 controls, MXCSR, XMM0/XMM15 and actual user FS/GS.
It repairs the continuation and edits saved RAX. Parent code checks all restored
GPRs and FP state, bases, DF, red zone and one handler execution before stdout
and exit42. FaultReturn leaves an NX continuation unrepaired and requires
sigreturn rejection/exit139. FaultFatal uses the real default fatal disposition.
Assertions require exit99. Every case must drain one actual generation through
exit, supervisor confirmation, off-stack reap and restored ownership.

A narrow read-only review found ARCH_SET_GS still returned EINVAL, making these
nonzero-GS proofs unreachable. The existing current-thread owner now supports it
under the same mapped-readable base policy as SET_FS. The gateway permits only
the exact requested base mutation on success0, preserving all other fields and
strict sigreturn base identity. Host controls exercise the actual gateway and
thread owner together, clone inheritance and per-generation changes.

Review also found a pending/nested delivery copy could reject valid ownership
after a setter edited frame150h/158h but before native WRMSR changed hardware.
LinuxThreadCopyOutput authenticates through LinuxNativeOwner/ValidateCallback;
ordinary PageAccess itself uses only LinuxSyscallAuthority, so this was not a
claim that every ordinary setter failed. Separate immutable callback-entry FS/GS
qwords648h/650h are now saved by resumable syscall and full fault capture and
used for actual CPU ownership. Desired return bases remain150h/158h. Allocation,
legacy non-resumable bytes and original privileged cleanup stay unchanged.
