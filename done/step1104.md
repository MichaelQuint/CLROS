# Step 1104 - Audit mapping ownership images and MTRR coverage

## Summary

Extended #94's implementation with an identity-image audit and a bounded
observed-MTRR validator. `PrepareIdentitySplit` traverses the complete reachable
four-level map, rejects aliases/shared/cyclic tables, requires WB/RW/NX identity
mapping for all arena pages and writes only a zero unused table. It returns the
original and replacement parent plus the exact entry/page indices without
publishing that parent. Missing table capacity fails before mutation.

`ValidateWriteBackMtrrRange` validates enabled variable-MTRR shapes and admits
uniform WB coverage above 1 MiB, either from the default type or a complete union
of WB variable ranges. Overlapping non-WB ranges, unsupported capabilities and
unsupported cache/SMRR/TME environments fail closed.

## Why

Preparing correct PTE bytes is insufficient when another virtual address aliases
the same physical page, the table arena is not owned/mapped consistently, or
MTRRs change the effective cache type. These checks are direct prerequisites of
the actual mapping transition. They validate supplied images/snapshots; the live
adapter still has to establish their provenance and execute the transition.

## Failures

No focused build/run failure. Review found two implementation gaps before
commit: an arena crossing a 2 MiB boundary could leave the selected free child
outside the affected leaf while recaching/removing existing table pages; and
an unsupported WC MTRR outside the target range could be admitted. Both are
corrected and covered by the final focused cases.
