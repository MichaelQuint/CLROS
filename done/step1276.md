# Step 1276 - Portable Linux qualification for broader runtime workloads

## Summary

Implement a separate Linux publisher/executor for the three broader upstream
workloads and strict cross-host build-input relocation. The implementation
preserves existing source-pinned producers and package/index identities. Four
manifest checks and four final qualifier checks pass. All three static Linux
NativeAOT builds, complete executions and independent portable audits pass:
29 commands, 758 sources, 19 producer files and 5,811 native/runtime inputs.
The owned builder/services stop and all three backing images remain unchanged.
Full-host/native/CLROS QEMU/ancestor qualification stays deferred until the
existing eight-issue batch is stable. No issue closure follows from Linux evidence.

## Why

The preceding three steps provide broader actual managed workloads. They need
their own pinned NativeAOT publications and complete source/native/syscall
inventories. Rebuilding host tooling inside the previous TCG builder took
35 minutes. Its portable managed build can run directly on Linux if the embedded
manifest interprets captured Windows paths without Linux Path.GetFullPath rules.
Retain exact inventory/raw hash checks rather than bypassing stale-build guards.

inspection/native-input hashes could disagree and earlier traces were not
rechecked after later publications. Add explicit executable hash equality before
execution and at final success, and reparse/compare every complete trace inventory
before success. New trace mutation/addition/deletion controls pass.

The first Linux attempt passed relocated tooling freshness but was stopped at
its identity-verified publish process group for this review repair. The terminated
publish returned zero after restore without its compiled inputs; the producer
failed closed at the missing produced-input path. No qualifier/publish/strace/ILC
process remained. Preserve the unqualified r01 output. The initial launch-only
inspection also used an unavailable BusyBox ps option; subsequent inspection uses
its supported options and did not restart the running job. The artifact-only
auditor initially had a wrong relative project reference; correct it before use.
The corrected r02 producer passes all final input/trace checks. Read-only review
confirms the two repairs.

A separate review found a real future guest-admission gap in the existing kernel:
musl's retained `.2976` suspension-worker trace removes its stack/TLS mapping
before its register-only exit60 tail at original ELF instructions
`0x4648b7`-`0x4648c6`. Current gateway post-call validation requires those removed
RSP/FS mappings, returning InvalidReturn after the successful mutation and
rejecting the next exit. Independently rerun the artifacts-only callback model
against the same production OS.Kernel.dll
`D64ECD4094CF6DBD42D9D892257BD5CF55EF8C0AC5A952B20C1F14D5B1B7C126`:
ordinary unmap returns Active then ThreadExited; self-unmap terminates with
InvalidReturn then rejects exit. Retain source/assemblies under
`self-unmap-review/` and root `self-unmap-independent-review.log`. This is a host
callback reproduction, not guest execution or the emitted tail/IRQ proof. No
kernel source is changed during this frozen Linux run.
