# Step 1047 - Deny managed console calls before backend availability access

## Summary

Fix #564: return the existing unavailable-services result immediately after a
denied firmware guard, before reading the console sink's availability getter.
Use the production adapter in the existing console tests and remove the copied
implementation from those tests.

## Why

The existing adapter checked the guard but then read `_sink.Available` to select
a result factory. Those factories eventually returned denial, yet the getter
could already have touched unavailable firmware state. Counting only line
writes missed that backend access. This was found while preparing M03-008 and
can be corrected independently of its pending guest prerequisite.

## Files changed

- `src/OS.Kernel/Platform/GuardedPlatformConsole.cs`: early denial before
  any sink member access; normal result validation and writes remain unchanged.
- `tests/OS.HostTests/PlatformConsoleGuardTests.cs`: reuse the five existing
  cases with the production adapter, implement the sink interface, count
  availability reads and remove the duplicated guard implementation.
- `docs/pal.md`: document the actual tested adapter and the host-only boundary.
- `done/step1047.md`: this record, reserved with the repository helper from an
  isolated inventory seeded with already committed step1046.
