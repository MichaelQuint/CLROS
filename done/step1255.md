## Why

The older terminal fault stubs saved only selected fault fields and clobbered
user GPRs before reporting. They cannot support genuine signal recovery. The
new explicit gateway stubs normalize [vector,error,RIP,CS,RFLAGS,RSP,SS], retain
original kernel-fault routing and jump without clobbering user registers.
The separate entry saves R14 through private GS and every other GPR/RAX before
scratch use; captures user FS/GS and FX; adopts the original kernel root and
aligned kernel stack; restores kernel FX and clears DF before C# delivery.
Only callback byte1 can install the complete checked handler image and IRETQ.
All other results use the original immutable cleanup path.

A narrowly delegated read-only audit found the earlier live callback check
compared active KERNEL_GS_BASE against saved supervisor KGS. After SWAPGS these
can differ legitimately. Active callbacks now authenticate actual user FS,
private GS=this gateway and KERNEL_GS=user GS, original root, phase/selectors and
IF/DF. Outside the active gateway, original supervisor authority stays intact.

Fault RIP/RSP are untrusted data, including inaccessible RIP or null RSP. A
separately admitted alternate stack may receive a handler, but original invalid
continuations cannot pass sigreturn. Hardware RF provenance is retained in the
kernel-owned LIFO frame tag; the user context records it while handler/return
clear RF under this restricted profile. Ordinary frames cannot borrow that
admission. Blocked/ignored/default fatal faults stage actual process shutdown139.
Reservation-aware page fault classification includes PROT_NONE, static user
ranges and unmapped holes. GP uses SI_KERNEL/zero address. Outside-user saved PF
errors sanitize the presence bit; diagnostics retain the raw hardware error.
