# Step 1096 - Prepare bounded rethrow bridges and measure compiler shape

## Summary

Development checkpoint for #596, a child of #90 (M04-021). Add deterministic
inner-throw and outer-rethrow COFF generation and host instruction-model checks.
Measure a real no-stdlib ILC fixture containing nested cleanup/catch, language
`throw;`, outer catch and compiled continuation. No EFI profile links the new
bridges yet, and no guest execution or rethrow acceptance is claimed.

## Why

The existing accepted single-finally profile returns from its catch. Rethrow
must instead recover the original active exception without an incoming argument,
validate the actual catch frame, and continue outside that handler. The pinned
.NET 10.0.12 [AMD64 implementation](https://github.com/dotnet/runtime/blob/v10.0.12/src/coreclr/nativeaot/Runtime/amd64/ExceptionHandling.asm)
and local pinned `Runtime.Base/src/System/Runtime/ExceptionHandling.cs` establish
the no-argument/active-exception ABI. This checkpoint prepares transfer machinery
and measures compiler output before implementing its admission.
