## Why

The existing span table has no opaque identity to distinguish recycled slots or
previous owner lifetimes. A live passive listener needs held half-open entries
and must retain a closed tuple until explicit cleanup/release. Every32-bit value
is a valid TCP sequence number, including zero after wrap; an initialization flag
must distinguish absent metadata instead of rejecting zero.

## Files changed

- `src/OS.Kernel/Net/TcpConnectionTable.cs`: nested unmanaged Owner/Handle/status
  API over1..64 zeroed, disjoint, aligned caller-owned entries and generation words.
  Reserve enters SynReceived; expected-state transitions establish/close/reset;
  closed entries remain held until release. Tokens join owner address, lifetime
  epoch and generation. Generations never wrap; exhausted free slots are skipped.
  Releasing a closed entry clears its complete bytes, including sequence/key data;
  retiring an empty owner clears generation words and prevents implicit reuse.
  Reject copied owners, stale/foreign/previous-epoch handles, invalid endpoints,
  missing sequence metadata, duplicate tuples, corrupt accounting/storage and
  unsupported transitions without mutating existing connections. Existing span
  method signatures and closed-slot reuse remain source compatible. Sequence
  metadata adds an initialization flag, changing its internal unmanaged layout;
  explicit zero now works while default metadata stays invalid.
- `tests/OS.HostTests/TcpConnectionTableTests.cs`: eight new ownership controls,
  including64 independent connections, closed tuple retention, generation
  exhaustion/reuse, real owner retirement/rebinding with a fresh epoch, metadata
  corruption, aliases, unicast endpoint policy and10,000 warmed allocation-free
  cycles. Existing seven span checks remain. Host-only Marshal.OffsetOf locates
  private metadata for explicit fault injection without exposing production
  internals or freezing byte offsets. Kernel code contains no reflection.
- `docs/networking.md`: current API/evidence boundary and sequence semantics.
- `.gitea/backlog/clros-issues.json`: only #148 development evidence; dependencies,
  labels, desired open state and live acceptance remain unchanged.
