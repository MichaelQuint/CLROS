# Step 1196 - NativeAOT-first roadmap, tracker reconciliation and project cleanup

## Summary

Adopt the user-approved NativeAOT-first route: retain the upstream application
runtime/musl payload and implement a measured Linux x64 syscall boundary in C#.
Qualify a pinned static `linux-musl-x64` payload before guest compatibility work.
Real local Kestrel precedes two isolated applications; local process isolation
precedes provider qualification. CoreCLR/framework-dependent workloads are later.
This is an architecture/backlog/tooling milestone, not guest app acceptance.

## Why

The old dependency graph put scheduler work behind networking and custom kernel
runtime completion, with Kestrel behind a speculative CoreCLR port. Existing
TCP tickets also contained storage-specific acceptance text and guest tickets
forbade their own required boot integration. Reuse accepted CLROS groundwork,
upstream application GC/EH, and exact reference source loci instead of adding
more disconnected contracts or a new runtime target prematurely.
