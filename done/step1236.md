# Step 1236 - Linux thread publication and resumable user-image bridge

## Summary

Development stage for #686 in draft PR #732, parent
`181fe810ebff2f06485ac3be4ef8c9cb4decfb35`. #191/#192/#686/#733 remain open and
claimed. LAN repository ID 9 and the exact #686/#733 ownership inventories were
read back. #733's two bridge test files and narrow next-create identity query
were added to its scope and read back before those shared edits.

`LinuxThreadServices` now owns one bounded process's Linux TIDs, independent
saved user images and signal masks over the existing `KernelThreadTable`.
Exact musl pthread flags publish fully initialized child metadata before the
real kernel Create. The child receives its own stack/FS, inherited mask, full
GPR/FP image and zero clone return. Parent TID copy uses checked user access;
failure after publication poisons execution and retains both workers for owned
shutdown. TIDs never wrap. No second scheduler or managed allocation is added.

Implemented calls are getpid/gettid, clone, set_tid_address, ARCH_SET_FS and
GET_FS/GET_GS, rt_sigprocmask, staged thread exit and process shutdown. A real
admitted kernel CALL capture precedes exit-time user mutation. Supervisor
confirmation and off-stack kernel reap precede slot scrub/reuse. User TLS and
stack mappings remain owned by the process memory owner. All other thread
operations return ENOSYS at this stage.

## Why

The fixed CPL3 gateway must restore its complete supervisor envelope before a
kernel worker parks or exits. The new 728-byte `UserImage` copies only user
frame/value/GPR/FP fields before cleanup overwrites its FP slot. Checked install
and explicit ResumeUser encoding restore those fields for a separately scheduled
worker, with R14 restored last. Original default-disabled entry bytes remain
covered by the existing independent byte controls. No supervisor header, root,
descriptor, guarded stack or kernel FP slot belongs to the saved user image.

The gateway's explicit thread callback uses a ref frame and separates Return,
Blocked, ThreadExited and Terminate. Only the exact successful ARCH_SET_FS may
change FS; all other return fields stay immutable. Blocking/thread exit are
staged actions, not native scheduler transfers. Old value-only dispatch remains
valid for the original non-thread diagnostics. The thread budget is bounded at
4,096; existing default budget remains 64.

The unqualified M09-009 diagnostic also had a wake-before-Park error: Park may
complete in place as Running. Its supervisor schedule now performs an explicit
real Yield in that case, with a focused lifecycle control. Prior step1234
records remain unchanged and did not claim native/guest acceptance.

## Evidence

A narrow independent review found two Linux ABI mismatches during this stage;
both were corrected and covered before commit. Primary source at Linux revision
`2687c848e57820651b9f69d30c4710f4219f7dbf` was then fetched/read directly:

- [fork.c lines1781-1786](https://github.com/torvalds/linux/blob/2687c848e57820651b9f69d30c4710f4219f7dbf/kernel/fork.c#L1781-L1786):
  set_tid_address records a raw pointer without accessing it. Exit attempts
  only checked, best-effort writes; an inaccessible pointer does not resurrect
  the exited thread. Unaligned accessible x64 storage is handled by the copy.
- [signal.c lines3316-3343](https://github.com/torvalds/linux/blob/2687c848e57820651b9f69d30c4710f4219f7dbf/kernel/signal.c#L3316-L3343):
  a valid new mask remains installed if oldset preflight/copyout returns EFAULT.
  Input faults precede invalid how; Linux int operations use their low 32 bits.
