# Step 1227 - Entry and repeated-timer host development

## Summary

Continued #188/M09-006 on top of stage-one commit
`86093885cb31c5dd856bb8ad56be4bf6b99ec0cb`. Added an unpublished Win64 entry/return
encoder and an idle-timer transaction over the private lifecycle deadline queue.

## Why

Normal return and deferred cancellation must reach the same captured CALL exit
path before supervisor-only reclamation. Timer reuse must retain the acknowledged
tick epoch and dirty hardware ownership; calling Arm after WakeReady is invalid.
The private lifecycle queue must remain authoritative during timer completion.

## Files changed

- `src/OS.Kernel/Threading/KernelThreadEntry.cs`: fixed 256-byte C#-authored
  Win64 first-entry encoder. Start(control, identity) returns exactly 1 to run
  Entry(argument), 2 to exit cancelled, or otherwise rejects. Normal EAX return
  and cancellation -1 become EDX for the existing CALL-capture exit stub. The
  impossible exit-resume continuation rejects. Emission is dry-planned before
  writes; byte verification admits a later captured descriptor without allowing
  it as a new entry. Live mappings and callback authority remain external.
- `ThreadContextSwitch.cs`: reuses the existing byte writer and planning
  admission internally. Public live admission still requires guard/mapping
  observations. No transfer encoding is changed.
- `KernelThreadTable.cs`: HandleIdleTimer rejects active workers/handoffs and
  mismatched epochs before MMIO, authenticates a safe timer tick against its
  private queue, then commits due completions. Detailed timer failure/borrow is
  retained; it performs no idle instruction, IRQ-frame redirect or switch.
- `SchedulerTimer.cs`: documents save-Ticks/Restore/Prepare/Arm and retained
  IDT/IST/mapping lifetimes; existing MMIO implementation is unchanged.
- Entry/table/timer host fixtures and `docs/pal.md`: controls and exact boundary.
