# Step 1015 - Bind and consume the original firmware service entries

## Summary

Add a one-use firmware binding for #64. Validate the supplied original x64 EFI
system/boot tables, their association, full declared-header CRCs and the actual
GetMemoryMap/ExitBootServices slots. Require each entry to belong to exactly one
owned-map code descriptor. Consume rechecks the tables, exposes the exact typed
entries and image handle once, and clears retained pointers. Unavailable firmware
mode clears the binding without reading firmware storage.

## Why

The terminal coordinator needs entries from the original firmware tables rather
than replacement callbacks. This helper checks those tables before the final-call
window without calling firmware or modifying table bytes. The eventual EFI adapter
must still establish original EfiMain provenance and readable table extents.

## Evidence

Source and checks are C#; generated evidence remains untracked under artifacts.

UEFI table HeaderSize governs CRC coverage, including extension bytes, with CRC
bytes treated as zero without changing the table. The local partial boot-services
struct's sizeof must not be substituted for the firmware's complete header size.
UEFI map attributes describe capabilities, not necessarily current permissions;
the binder checks code classification, leaving actual page permissions to the
adapter. References: UEFI 2.10 sections 4 and 7 at
https://uefi.org/specs/UEFI/2.10/04_EFI_System_Table.html and
https://uefi.org/specs/UEFI/2.10/07_Services_Boot_Services.html.

## Deferred work

These are controlled host checks and no-stdlib compilation, not real EFI binding,
ExitBootServices, privileged execution or QEMU proof. CRCs detect corruption;
they do not authenticate malicious firmware or forged pointer provenance. Retain
one exclusive original state without copying/resetting it or aliasing outputs.
The owned map must remain stable while binding; actual CR3/mapping authority and
valid readable table storage remain caller obligations.

complete retained mapping and native stack review, owned COM1 markers, live
