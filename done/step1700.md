## Why

qualifier files. Current-source checks still expected the original monolithic

would erase the original evidence boundary instead of admitting the new layout.

## Files changed

path/hash pairs to independently reviewed current path/hash sets. Unknown paths
retain their original expectations; a known path with a different original hash
rejects. Expected hashes are fixed reviewed inputs, never calculated from the
current files to make them pass.

NativeAotHelloGuest and NativeAotRuntimePackage expand current checks through
that map. Runtime app inventory derives from the selected expanded paths, while
retaining override, reparse, size and entry-limit checks. Original Sources,
SharedSources and historical receipt joins remain unchanged.

Within tools/OS.Tooling, declarations named NativeAotPayload and, when selected,
NativeAotRuntimePayload are reserved to their reviewed files. This deliberately
applies regardless of namespace, nesting, arity or declaration kind. Ordinary
references are allowed. Conditional branches, generated-looking filenames and
markers, and nested bin directories participate; only root bin/obj/artifacts
are excluded. It is a conservative name reservation, not compiler-input discovery.

HelloGuest, RuntimePackage and OriginalRuntime source mutation fixtures follow
the selected current paths. NativeAotCurrentSourcesTests adds original-hash,
hidden-declaration, malformed-source and missing-member controls. No kernel,
Linux ABI, package policy, instruction-index authority or resource limit changes.
