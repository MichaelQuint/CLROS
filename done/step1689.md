# Step 1689 - Kernel type extraction and independent source review

## Summary

Extracted 434 non-storage kernel source families into 2,132 files. Nested
identities use partial containing declarations; executable members, field and
initializer order, attributes, layouts and conditional branches are preserved.
The host checker now recognizes multiple compatible declarations of the same
logical partial type, while rejecting distinct namespaces, arities and kinds.

## Why

Apply the approved one-type-per-file convention without moving Linux semantics
into reusable kernel contracts or changing public APIs. This is structural work;
it makes no performance or native execution claim.

## Files changed

The exact source map is `artifacts/refactor-r01/kernel-repair-r02/receipt.json`.
It covers non-storage `src/OS.Kernel` families and their associated helpers.
`RepositoryCodeStyle.cs`, `CSharpSourceProfiles.cs` and checker tests cover logical
partial identities. `ThreadContextSwitchBytesTests.cs` reads the extracted
`ThreadContextSwitch.StubWriter.cs`; it still compiles the actual production
method and fields, with the same assertions.

## Failures

The first normalizer altered malformed XML-looking documentation and left
trailing whitespace. A repair from authenticated originals preserves comment
text and multiline literal tokens. Repair r01 then encountered a Windows mapped
file and stopped. Recovery authenticated every output as either the original
published bytes or regenerated bytes, backed up the entire mixed state, and
completed with verified temporary files and atomic replacements.

KernelThreadTableTests r01 was invalidated by reserving this evidence file during
its repository snapshot. It ran zero checks; r02 passed with the entire tracked
tree frozen. ThreadContextSwitchBytesTests r02 failed because its source fixture
used the old helper path; the corrected r03 passed all 23 checks. Failed receipts
remain failures.
