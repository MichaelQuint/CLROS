# Step 1695 - Bound boot source contracts

## Summary

BootSequencePlanTests now follows actual EFI type and method identities across
partial files. The r35 candidate passes 57 focused host checks and repository,
contract and whitespace checks. API expectations remain independent contracts.

## Why

The old guards depended on a monolithic EfiEntry.cs, a fixed number of preprocessor
regions and the first physical occurrence of a call. They broke after structural
moves and could miss a call whose type and method were on different lines.

## Files changed

- BootSequencePlanTests.cs and .SourceBoundaries.cs replace those readers with
  actual default, disabled Diagnostic, stage-one/two/three and syscall profiles.
- HostBootSourceGuard binds member signatures, direct calls and other method
  references. It rejects host-only types, added APIs/attributes, forbidden or
  indirect calls, wrong owners, duplicates and dormant local-function/lambda calls.
- Linux preparation/entry/diagnostic calls retain their per-method order and
  family-wide uniqueness. Callback addresses must reach the actual reference
  field and stub parameter without narrowing or transforming the x64 address.
- HostBootSourceGuardTests supplies moved/aliased positive cases and mutations
  for signatures, conditional leaks, indirect calls, duplicates, ordering,
  callback destinations, parameter/return attributes and address truncation.

The expected 74 BootSequence and 86 Probes members were recorded only after
comparing complete active member tokens against d47f8558. The peer independently
matched all 13 original source inputs, including the 11 authority partials, to
the original Git objects. The API inventory is sorted; this is not a new
initializer-order proof or permission to reorder runtime state.
