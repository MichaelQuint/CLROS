# Step 1313 - Bounded host packet-peer transport development

## Summary

Add the host transport needed for independent Ethernet injection into the planned
continuing-network/TCP batch. Seven focused checks use actual IPv4 loopback sockets
and pass. This does not launch QEMU or supply guest/network acceptance. The batch
#691 -> #148 -> #149 -> #150 -> #151 -> #152 -> #153 remains open under #734.

## Why

The existing user-network backend supplies ARP/ICMP peers but cannot inject the
batch's arbitrary bad ACK, loss, reorder and timeout cases. Reuse QEMU's legacy
socket-netdev wire contract: one big-endian32-bit length followed by Ethernet
bytes. The transport is deliberately separate from the pending protocol script
and actual runner/profile wiring.

## Files changed

- `tools/OS.QemuRunner/QemuEthernetPeer.cs`: one ephemeral IPv4 loopback listener,
  one accepted connection and a finite1ms..5min lifetime including accept. It
  bounds Ethernet frames to14..1514 bytes without FCS, performs exact fragmented
  reads, serializes each direction, and permits independent read/write progress.
  Invalid caller buffer/size or overlapping operations consume nothing. Invalid
  wire lengths, EOF/truncation, cancellation and I/O failure close the session;
  no reconnect, resynchronization, unbounded packet queue or background worker
  is introduced. Dispose closes owned sockets and interrupts pending operations.
  Counters advance only for complete frames. Borrowed buffers must remain valid
  and unchanged until their operation completes.
- `tests/OS.HostTests/QemuEthernetPeerTests.cs`: seven explicit loopback cases
  cover independent length bytes, minimum/maximum frames, fragmented prefix and
  payload, concatenated frames, duplex transfer, preflight preservation, invalid
  wire lengths including uint.MaxValue, empty/partial EOF, canceled accept/read,
  actual lifetime expiry, duplicate accept/overlapping read and disposal.
- `docs/networking.md`: implementation and pending-QEMU boundary.
- `.gitea/backlog/clros-issues.json`: only #691's development evidence changes;
  dependencies, labels, open state and acceptance requirements are preserved.
