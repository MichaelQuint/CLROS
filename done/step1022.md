# Step 1022 - Prepare terminal fault diagnostics and accessed-image checks

## What changed and why

The permanent owned hierarchy needs terminal fault handling without firmware
output, and its post-adoption audit must tolerate hardware-set accessed/dirty
bits. Add both pieces to the existing #64 implementation.

`FirstExitTerminalFaultStub` saves all 15 general registers above the existing
normalized interrupt frame, admits one original prepared context, reads CR2/CR3,
and calls the caller-authenticated owned Win64 diagnostic target. Any refusal or
callback return enters a CLI/HLT loop; there is no RET, IRET or CR3 write. Its
184-byte frame is shared with the C# reporter. The native call needs at most
55 bytes below that frame for alignment, shadow space and the return address;
this excludes the compiled callback's own stack requirements.

The reporter validates normalized vector/error-code semantics and uses the
existing checked COM1 backend and panic formatter with `boot` / `exit-fault`.
It consumes the context before reporting, suppresses retries, and retains a
failed state on malformed input or bounded serial timeout. The retained arena
reserves the fault context at byte 1024 of page zero, with explicit size checks
against the transition context and page boundary.

`AuditRetainedAccessedImage` reuses the hierarchy audit. Only accessed bits and
dirty bits on writable leaves may differ from the prepared image. Table targets,
mapping counts, page zero, permissions and unused tables retain the same checks.
The original pristine audit still refuses these hardware changes. This observes
supplied memory and does not claim which CR3 is active or what a TLB contains.
