# Step 1025 - Validate the retained layout and exact descriptor targets

## What changed and why

Join the first-exit mapping pieces in `FirstExitRetainedMappings.WriteRanges`.
The bounded output includes the original image sections, five non-guard arena
intervals, three authenticated code pages and the original allocator backing.
The existing table builder adds its own RW/NX arena. All five allocations must
be disjoint, including reserved gaps; page counts, root limits, cache policy and
output aliases are checked before copying the final declarations.

The adapter declares its entry, diagnostic and fault callbacks plus adapter
state, allocator state and copied ACPI byte extents. These must fit the original
image's RX or RW/NX sections as appropriate. The original arena handle must lie
inside the retained adapter state, rather than the outgoing firmware stack.
These are containment checks, not proof of the declarations' provenance or
readiness. Other independent allocations must not be silently omitted.

`FirstExitOwnedArena.ValidateDescriptors` reads back the complete fresh GDT,
firmware-CS alias, TSS and reserved tail, final/bridge IDTs and pseudo-descriptors.
It verifies original buffer pointers before following them, exact owned stack
tops, all normalized vector targets and zero observation fields before entry.
Code-bundle admission now requires this check, so mismatched descriptors cannot
be paired with otherwise valid generated code.
