# Step 1261 - Separate focused upstream suspension workload

## Summary

Development #687/#733 implements a separate .NET 11/C# 14 suspension-only app
and strict captured-output validator. One dedicated managed worker retains an
array, interior reference and thread-static value across two blocking compacting
full collections; the main thread verifies its own roots/TLS and requires a real
join before success. There are no application Task/ThreadPool/timer API calls.
The Release managed DLL runs on the Windows host. No NativeAOT payload is built
or admitted by this step; original Hello/runtime/Minimal API sources and the
NativeAotPayload qualifier remain unchanged.

## Why

#687 explicitly requires this separate focused fixture after unchanged Hello.
The existing comprehensive runtime app always runs Task/timer work and cannot
be an earlier suspension prerequisite. Preparing this concrete workload lets
the current eight-issue batch qualify its upstream consumers together later,
without replacing or reconfiguring the original qualified payloads.

The source/output protocol records worker progress before collection, immediately
after return, and after a subsequent increase. Comparing only to the pre-GC
sample could accept activity that happened before collection; that race was
corrected before execution. A worker that stops after GC returns cannot pass.
Console output alone cannot prove that native activation/suspension occurred.
