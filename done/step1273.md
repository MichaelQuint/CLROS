# Step 1273 - Separate GC-only repeated thread lifetime stress workload

## Summary

Implement a separate real managed workload for #193's broader root/context and
repeated thread lifetime cases without changing the original pinned consumers.
Nine explicit full collections across three lifetimes complete on Windows;
fifteen workers join with checked object/interior/TLS state. Six focused checks
across two fixtures pass, zero reuse/failures. No Linux publication, native build,
full-host suite or QEMU runs. Keep the original eight-issue batch active.

## Why

The separately qualified focused suspension app retains its exact one-running-
worker/two-collection contract. Broader parked/join/sleep/exit and repeated-lifetime
coverage needs a distinct app and future producer identity. Use the application
runtime's existing GC and thread primitives; do not add a second kernel collector
or change accepted package/index/source receipts to hide the expanded behavior.

## Files changed

- `apps/NativeAotSuspensionStress/NativeAotSuspensionStress.csproj`, `Program.cs`:
  C#14/.NET11 workstation-GC workload. Each lifetime creates five actual managed
  threads with running, event-waiting (spin disabled), sleeping, join-blocked and
  exit-requested roles. Object/interior references and per-thread TLS stay live
  across collections, with zero-initialized TLS required on every new worker.
  Wait states are sampled before each collection; the first
  also checks the sleeping phase. Main/worker root checks, real collection counts
  and fresh progress are required. Each operation completes once, each thread
  joins, and event resources release after all started threads have joined.
  Startup/progress/wait/join are bounded; the process owner independently bounds
  GC itself, which cannot safely be cancelled in the workload.
- `NativeAotSuspensionStressGuest.cs`: strict entire fourteen-row observation
  validation, global collection monotonicity, fresh worker progress per lifetime,
  complete joins/root/TLS/operation witnesses, bounded strict UTF8 file reads.
  It grants no prepared program, producer or execution authority.
- `NativeAotSuspensionStressTests.cs`: independent positive and malformed/missing/
  reordered/extra/overflow/lost-progress vectors, bad file encoding/size/late
  failures, retained input bytes and released handles. Actual Windows managed
  execution plus invalid arguments use the existing bounded ProcessRunner and
  preserve stdout/stderr. The new app is explicitly rejected by original pinned
  program/package selection, rather than being treated as a qualified payload.
- Canonical app-model and PAL status docs. No original app, qualifier, canonical
  package/index, native source or existing guest selector changes.
