## Why

Combining the previously separate Linux clock and PCI/APIC profiles requires
distinct helper offsets, complete allocation inventories and a separate worker
layout. M16-008 uses 64 retained pages: four code pages, eleven metadata pages,
one guarded switch stack, four guarded worker stacks and an IRQ stack/IDT.
Existing M09 profiles retain their original 32-page layout. Existing actual
PTE/CPU ownership checks publish/audit/restore the selected shape.

PCI now appends its allocation instead of replacing the Linux package/backing
entries. HPET and ECAM each contribute their own allocation/range capacity:
M16-008 admits 19 allocation slots. The sealed Linux ledger has 17 entries,
including the retained worker pool. Linux package/startup allocations reject
pool overlap before buffer read/zero/emission. Device MMIO remains a mapping
declaration, not a firmware allocation receipt.

LinuxThreadProgram bindings now retain the scheduler's exact slot argument
separately from callback control. The native Start callback must still verify
that argument against the actual table generation before entry.

The ELF uses returned PID/TID/fds, independent parent/child stacks and FS pages,
mask inheritance/query/update/isolation, a blocking pipe, private gate wait/wake,
shared clear-child-TID join, wrong-value EAGAIN and a genuine relative 1ms futex
timeout. It checks R12 isolation and stack sentinels. Parent exit_group42 follows
`M16_THREADS_OK!`; child exit60 precedes the real join; assertion failure exits99.
The 18 parent and 11 child syscall return inventories exclude the synthetic
child clone return, which has a separate recorded RIP. No program has executed.

QemuProfiles refuses M16-008 with m16_008_native_owner_unbound until its native
consumer is attached. Direct EFI entry also fails before the old single-thread
path can enter user mode or emit ancestor success. No M16-008 READY is emitted.
