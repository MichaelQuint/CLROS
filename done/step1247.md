## Why

Step1246 covers readability and capacity, but not a wake caused solely by peer
close or process exit with a retained read. These variants complete the missing
mechanical inputs without another scheduler, probe or native path:

- PipeReadClose: parent parks on an empty pipe. Child closes the write endpoint
  and exits. Parent resumes with EOF, observes cleared TID and closes its read
  endpoint. Both real workers must be reaped off-stack.
- PipeWriteClose: parent fills the 4,096-byte pipe then parks on an atomic
  four-byte write. Child closes the read endpoint and exits. Parent must resume
  with EPIPE, observe cleared TID and close its write endpoint. The existing
  mechanical owner explicitly ignores SIGPIPE; this does not add delivery.
- PipeShutdown: parent parks on a genuine one-millisecond futex timeout; child
  parks on an empty pipe read. Actual idle IRQ/HPET processing makes the parent
  runnable. After ETIMEDOUT, exit_group42 cancels the child. Its existing native
  Exiting path must bypass user installation/resumption, drop the retained pipe
  operation at CommitExit, clear TID and reap. The child's user read continuation
  jumps directly to failure99, so accidental user resumption cannot pass.

An initial zero-byte I/O call binds each peer descriptor to an earlier actual
row without changing pipe contents. The parser cross-checks subsequent close/
I/O arguments against that row and the independently emitted ELF; no fixed fd
allocation is assumed. Source review added this binding before focused runs.

The compiled package command accepts an optional explicit variant. CreateNew
still preserves existing output. Retained input preflight admits only complete
byte-identical canonical packages, with bounded input length and rewind on
success. A manifest name alone grants no protocol selection.

Runner ordered markers retain the common parent/thread envelope. Variable call,
completion, exit, reap and tick order belongs to the complete package-specific
validator; those records remain required where applicable and cannot be forged,
dropped or replayed. Close-only cases need no timer record; Threads and
PipeShutdown still require genuine elapsed HPET timeout rows. Original ancestor
startup/service/package/PCI/APIC composition and root binding remain unchanged.
