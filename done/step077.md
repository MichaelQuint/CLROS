# Step 077 - Executable Stub Bundle Layout Plan

## What Changed

- Added `ExecutableStubBundlePlan`, a host-tested deterministic layout planner for future generated diagnostic stubs.
- Added stable slot kinds for COM1 `Out8`/`In8`, descriptor-table `lidt`/`lgdt`/`ltr`, invalid-opcode probe, and null-write probe payloads.
- Calculated aligned offsets, total payload length, required memory bytes, and fixed per-slot offsets from caller-provided slot lengths and an existing `ExecutableStubMemoryPlanResult`.
- Rejected duplicate slots, unknown slot kinds, zero-length slots, invalid memory plans, insufficient memory plans, and overflow.

## Why It Changed

Issue #94 needed a layout boundary between generated stub byte plans and future executable memory. The project can now prove deterministic placement before any work copies bytes, changes page protections, or invokes generated code.
