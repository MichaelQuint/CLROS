## Why

The final M01-025 review identified one boundary that its source/build evidence
does not close: dynamically written instruction bytes must be architecturally
serialized before first execution. The current .NET 10 no-stdlib path cannot
honestly express the required `CPUID`/equivalent publication primitive as
ordinary first-party C# without importing an unavailable runtime helper. The
smallest auditable design is therefore a deterministic C# host generator that
emits one exact AMD64 COFF text symbol, a separate canonical link/artifact
integration, and a separate `EfiEntry` call-site slice.

Preserving that split in the version-controlled backlog prevents a later agent
from treating M01-025's host oracle or EFI build as proof that generated bytes
were safely published or executed. It also exposes the generator-only leaf for
parallel work without granting it ownership of `CLROS.slnx`, `OS.csproj`, or
`EfiEntry.cs`.
