## Why

The accepted immutable package in step1199 needs continuing owned service time
and a protected Linux image/startup boundary before application entry. Reuse
the existing HPET access and revoked firmware capability mechanisms in explicit
child profiles; preserve direct legacy profile conflicts and default-off probes.
The service pump is single-CPU cooperative work. The owned controller explicitly
requests stop; this is not OS threading, a scheduler, power-off or external admin.

## Development integration update

The service child reuses HPET and copied firmware-capability mechanisms without
selecting the direct legacy clock/revocation profiles. The retained allocation
list appends HPET after package/startup resources. Four timed iterations request
owned stop; all eight copied capabilities must deny with unchanged outputs and
provider counts. The parent package and ordinary policy retain their selection.

The loader child reserves image/stack backing and a separate 128-page table
pool before exit. It borrows the existing firmware RNG acquisition with its own
original state, immediately clears borrowed firmware pointers, zeroes backing,
builds fixed-address PT_LOAD and a 16-byte-aligned argv/envp/auxv stack, audits
NX/W^X/U-S mappings, and uses a C#-emitted Win64 bridge to adopt the candidate
root for original first-party read-back and restore the kernel root. Pre-exit
failure releases the new allocations; post-exit failure clears/unpublishes them
while retaining reserved ownership. No ELF entry or TLS thread pointer is set.
The live backing limit is 4096 pages, preserving the existing identity-builder
cap; the host geometry core admits larger spans separately. Both children can
compose: startup precedes the service controller's shutdown.

shared AsciiArgumentSplitter and independent fixtures, plus additive strict
QEMU service/startup validators. Shared boot/probe/project/profile/admission

unsafe code only to call the pointer-based host oracle; #697 records this scope.
