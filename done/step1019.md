# Step 1019 - Load the OS project in Visual Studio 2026 Insiders

## What changed and why

Issue #555: Visual Studio's full-framework MSBuild failed to load `OS.csproj`
with MSB4186 because the imported serializer targets called
`System.IO.Path.TrimEndingDirectorySeparator`, an API unavailable in that host.
Replace all five calls with `GetFullPath(path + "\\.")`, which normalizes the
already absolute paths while preserving drive roots. Update the publisher's
canonical XML hash to match this exact targets change; retain its authority
checks, no-stdlib settings, and existing GC generator conditions.

## Failures and corrections

The initial ad-hoc path check hit PowerShell 5 trailing-backslash argument
quoting; PowerShell 7 passes the intended argument unchanged. Its Core-host
prefix also needed explicit array construction. An initial override assertion
expected rejection, while MSBuild actually recomputes that private property;
the final check verifies the resulting authoritative path. An initial publish
attempt used an unsupported output directory and was rejected before building;
the successful command uses the required `artifacts/efi` directory.
