# Step 1174 - Constructor-failure transfer calibration and bounded body branch

## Summary

The first real constructor throw exposed a conservatively unsupported compiler
body branch in the Read frame. This profile now interprets that exact pinned
two-byte branch while retaining the raw context. Both real throws, the wrapping
and outer catches, compiled continuation, failure bookkeeping, rooted collection
and canaries complete in development. Stable batch/full-host qualification is pending.

## Why

ILC returns from the static-base helper at Read+33: EB F0 branches to Read+19,
MOV RAX,[RBX]. Generic UnwindOne deliberately rejects this instruction as an
unsupported epilog. The current issue needs this one original compiler path;
the general unwinder contract and unsupported branch behavior remain unchanged.

## Files changed

ConstructorFailureProbe checks the original PC, retained static-base RBX, both
branch bytes and target instruction, then copies the POD context and interprets
the branch before the existing body unwind. Raw scratch context is preserved.
Failure-only unwind diagnostics report status and expected/actual scalars.
EfiContracts.Sources refreshes the source pin. QemuTranscripts.ConstructorFailure
and its fixture use the actual enum Success value (one), replacing a mock zero.
Native controls add a rehashed Read branch-displacement rejection.
Existing status docs retain the pending stable-batch boundary.
