# Step 1690 - Dynamic host source discovery checkpoint

## Summary

The combined refactor replaces fixture source-file assumptions with compiler
identities and an actual build input inventory. This is an intermediate working
candidate, captured at integration HEAD `060dd93f` plus its uncommitted changes.
It is not completion of PR814 or renewed RC3 acceptance.

The six frozen r12 focused runs pass 125 checks with unchanged inputs and zero
reuse. Their producer is the successful `dynamic-catalog-build-r15` build.

## Why

One-type-per-file extraction exposed fixtures that read the former containing
file, guessed preprocessor symbols, counted a fixed source list or keyed test
dependencies by a basename. These assumptions couple verification to layout.
Discovery now follows evaluated compiler inputs, selected profiles, metadata
type identity and bound calls. Expected bytes, status handling, layer boundaries
and reviewed native output ownership remain independent assertions.
