# Step 1036 - Seeded churn native adapter development evidence

## What changed and why

Prepare #83's freestanding adapter while #82's acceptance checkout remains frozen.
The adapter validates the original collector's completed phase, retained static
base and compiled child payload, runs three 64-round seeded workloads on the same
collecting owner, verifies exact counters/fingerprints and monotonic identities,
and checks the original stack canaries before and after the workloads. It emits
bounded ordered M04_CHURN records and CLROS_M04_014_READY only after success.
Failures emit a reason/phase/check-count record and use the existing fail-fast
spin. There is no new runtime stub or canonical EFI source/profile admission.

## Failures

The first negative-control harness incorrectly required CPU HLT=1, although the
existing RuntimeFailFast.Halt implementation is a while(true) spin. A second
harness required the later sampled RIP to equal the spin entry and failed that
assertion after observing the correct EB FE loop; the later RIP cause is not
established. Both failed receipts/helpers are retained. Final v3 checks the actual
immutable spin bytes and quiet serial without those unsupported assumptions.
Neither failure required a production-code change.

calls on the retained heap. The canonical build excludes the adapter, and its
