# Step 1006 - Trace, reclaim and reuse through the retained allocator

Issues #82/#552 now implement bounded synchronous collection in host-testable
production code. After complete validation, the collector traces explicit
receipt roots and one original retained static base, clears unreachable blocks,
and retires the original allocator's live records. Subsequent allocation uses
those freed blocks with fresh identities. This is real same-owner reuse, not a
live-set plan, cursor reset or an independent demonstration heap.

The original 80-byte allocator prefix and allocation commit path remain. An
explicit one-way opt-in before allocation requires 5520 bytes of caller owner
storage, including 170 records. No public free/reset operation is added. The
high-water observation does not rewind; allocation identities cannot wrap.
Existing retained-root query code works through the updated receipt validation.

`BoundedNonMovingCollectorExplicitRootEnumeration.cs`, their existing host-test
