# Step 1507 - Observe real HTTP streams for the owned race controller

## What changed and why

Supply the actual transport prerequisite for guest race integration. Logical
attempt IDs alone cannot identify real connected streams or their raw I/O.
`CaptureObservedSignalRaceAsync` now owns three persistent HTTP/1.1 role handlers
for serialized control calls, pending churn and pending race. It runs the same
bounded controller, disposes every handler/stream, joins recorder connects/I/O,
then retains a fresh `.wire.json` beside selected/attempt reports. Partial errors
retain their raw prefixes before propagation. A second snapshot/write failure
preserves the controller error too; failed I/O joins grant no final snapshot.

Reuse the existing bounded connected-stream recorder without copying its I/O
implementation. Its internal explicit web profile has separate strict roles,
routes, purposes and `clros.web.signalrace.wire.v1` schema. Existing quota public
entrypoints still select their default strict profile and schema. Generic copied
record types remain shared. Attempt IDs equal observed exchange IDs; actual
request writes name their streams, including any real retry. Reads retain
directional offsets and ExchangeId0 until independent HTTP FIFO framing.

Successful reads and attempted write bytes remain explicit. Failed/canceled
transfers retain unknown counts; no bytes are invented. Captured local endpoints
and elapsed100ns ticks imply no NAT tuple, packet identity or guest clock. The
new copied transport join checks exact logical IDs, method/path, terminal outcome,
status and bounded raw body; it does not claim HTTP framing or packet authority.
