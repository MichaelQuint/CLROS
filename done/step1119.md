# Step 1119 - Gate native work on the complete fast phase

## What changed and why

The migrated runner grouped cases by class. A class containing native work could
therefore delay its fast checks until native work had already begun. Full runs
now partition mixed classes into stable `.Fast` and `.Native` groups, finish all
selected fast cases, collect their failures, and start native work only if that
phase passed. Native work remains exclusive. A blocked run is incomplete and
unsuccessful; its successful checkpoints remain available for resume.

Files: `tests/OS.HostTests/HostTestRunner.cs`, `HostWorkerScheduler.cs`,
`HostTestRunnerTests.cs`, and `docs/host-requirements.md`.
Single-lane group identities, case selection, original case markers, provenance
keys, output admission and the full-success rule are retained. This is a test
orchestration change, with no production or native runtime source change.
