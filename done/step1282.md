# Step 1282 - Explicit runtime budgets and broader output decoding

## Summary

Adds finite native execution budgets for the larger thread policy, raw stdout
decoding for all three Linux-qualified broader apps and ordinary requeue
accounting in the common transcript model. Continues the existing eight-issue
batch; no new QEMU selector or accepted guest is introduced.

## Why

The old 128 APIC epochs and 512 driver steps do not measure elapsed time. The
broader suspension workload performs actual one-second sleeps and all broader
apps have 20-second operation timeouts across three rounds. Their original
Linux qualification independently bounds the whole process to five minutes.
Use actual monotonic nanoseconds and separate event limits; do not convert the
uncalibrated APIC reload into time or fabricate timeout completion.

The service requeue implementation from step1281 also needs a matching
observation model. Address FIFO changes on a move; the scheduler's original
deadline insertion order must survive.

## Files changed

- New `LinuxThreadExecutionBudget.cs`: original <=8-worker limits remain
  128 epochs/512 steps; larger policies admit 8192 epochs/16384 steps and
  300,000,000,000 actual monotonic nanoseconds. Reject bad/repeated admission,
  clock regression, exhausted counts and expired time without mutation.
- `EfiEntry.LinuxThreads.cs`: retain and initialize the budget before any worker
  starts. The existing 8192-byte control allowance and 112448-byte conservative
  metadata bound remain; final native sizeof/ABI/stack review is still required.
- `EfiEntry.LinuxThreadRun.cs`: check the larger policy's actual clock only on
  restored supervisor steps. Expiry stages original owned Shutdown/continuations;
  the separate finite drain budget remains. No elapsed check rejects an already
  owned interrupt acknowledgement, restoration or worker exit.
- `EfiEntry.LinuxThreadTimer.cs` and `.LinuxUserInterrupts.cs`: use the admitted
  epoch ceiling. APIC reload/divisor and real HPET-driven futex deadlines remain.
- `NativeAotThreadingOutput.cs`: exactly five known apps, routing the three
  broader names to their original complete output validators. Per-write and
  total stdout bounds remain 4096; raw tail remains 8 MiB. Preserve raw inputs,
  strict UTF8/framing, segmentation and immutable derived output.
- `QemuTranscripts.NativeAotThreading*.cs`: separate address FIFO from deadline
  FIFO; ordinary requeue returns actual wakes plus moves, without completion.
- New budget/output controls and extended complete synthetic transcript vectors.
- Exact EFI project link, conditional evaluation, source/project identities and
  the existing PAL/app/diagnostics/EFI docs.

## Evidence

- Budget controls cross the old epoch/step limits during an independent numeric
  one-second elapsed observation, admit the final valid count/time boundary, reject
  exact expiry/regression and exercise near-long.MaxValue arithmetic without
  adding a deadline or overflowing. These are value contracts, not hardware time.
- Complete synthetic raw outputs cover all three broader apps, CRLF splits,
  arbitrary row segmentation, complete/failure/extra/wrong-app/UTF8/framing
  rejection and immutable results. No synthetic output is a guest capture.
- A complete suspension vector moves an older waiter behind the existing target,
  checks zero source wake and same-key count, resumes the actual target winner,
  then moves the remaining borrow back. A complete ThreadPool vector changes
  address FIFO while equal-deadline expiration retains original scheduler FIFO.
  Forged counts, mode, target, negative move and premature wake mutations reject.
