# Step 1264 - Bind unchanged Hello instruction boundaries to the qualified ELF

## Summary

`NativeAotHelloProgram` now admits an immutable instruction/syscall lookup only
from the exact canonical Hello package, current app/producer inputs and a
complete reviewed LLVM-derived index. The actual pinned package and disassembly
pass. Eight focused host checks and five separate actual-input mutation controls
pass. No QEMU input selector or transcript gate is relaxed by this step.

## Why

Real Hello has variable runtime call paths and genuine user IRQs, so the fixed
mechanical instruction inventories cannot validate its captured RIPs. A raw
0F05 scan finds 168 matches in executable bytes, including two inside other
instructions. The frozen LLVM decode contains 166 actual SYSCALL instructions.
Both exact syscall continuations and ordinary instruction boundaries are needed
by the complete Hello syscall/scheduler validator; stdout alone is insufficient.
This is part of #687/#733 in the original eight-issue batch, not a replacement
for actual Hello execution or the remaining runtime consumers.

## Files changed

- `tools/OS.Tooling/NativeAotHelloProgram.cs`: parse bounded LLVM rows against
  an admitted static ELF load plan; reject bad bytes/lengths, unknown rows,
  opcode/mnemonic mismatch, unordered/overlapping rows and non-file-backed or
  non-executable extents. The private constructor retains fresh private sorted
  arrays; only exact package/source/count/index admission creates the public
  immutable instruction/syscall lookup. Every syscall continuation must also
  be an admitted instruction start. No mutable input or array is exported.
- The public value-only Inspect report intentionally grants no prepared-program
  authority. It permits partial parser controls; it is not a generic x64 decoder.
  Only the fixed complete digest prevents an untrusted decoder from inventing
  alternate boundaries that still match ELF bytes. Read uses bounded read-only
  locked snapshots and strict UTF8, writes/executes nothing, and throws on errors.
- `tools/OS.Tooling/ToolCommand.cs`: `linux hello-program <hello-package>
  <llvm-disassembly>` performs strict preparation and reports canonical counts
  and index digest, with ordinary tooling failure markers. Help lists the command.
- `tests/OS.HostTests/NativeAotHelloProgramTests.cs`: four independent cases
  cover canonical binary serialization, operand-byte false matches, presentation
  normalization, malformed/order/backing/permission/syscall controls, same-count
  forged boundaries, synthetic package rejection and file-size/UTF8/CLI failures.
- Existing app-model, QEMU and EFI docs explain how this admission fits the
  complete still-required Hello validator. Original apps and NativeAotPayload.cs
  remain byte-identical; no binary, generated instruction list or native source
  is committed. The extra file scope was claimed/read back in #733 before edits;
  compiled `done reserve` allocated this evidence step before source changes.

## Evidence

Pinned ELF: 1,241,768 bytes, SHA256
`E7EBAD7E939BE69131E86AE486549651A8D22D7435E8E20B1375FEA44602C6FE`.
Canonical package: 1,242,104 bytes, SHA256
`84C4CABD1CEA33EE01FB4E799D0C935129BDC3AF24D85DB368A1226350F60DEF`.

The earlier read-only decode used existing configured LLVM 22.1.3,
`llvm-objdump.exe` SHA256
`7E726D87FE123F10653998A78DC6A15492FB931F1E6DE7265DF7D923FC81A210`,
with `--disassemble --print-imm-hex`. Its 14,660,849-byte dump is
`artifacts/hello-elf-disassembly-r01.log`, SHA256
`60AEF781CADC0FE2A08CEABFB724BED85ED53184E6F85A7352E7BB6FC79A1122`.
The decode covers .init, .text, __managedcode, __unbox and .fini with no unknown
instruction row. This step consumes that retained decode, without rerunning it.

Canonical index SHA256:
`13A2F6FF65B4A2EE0137EDE2C59CFD174D32C91656B54E7E3F09794D49C6F0FB`.
Hash input starts with ASCII `CLROS_HELLO_INSTRUCTIONS_V1\n`, then each ordered
row's UInt64 little-endian address, byte length, exact instruction bytes and
single syscall-classification byte. Presentation paths/line endings/spacing
cannot change the admitted boundary set. The same-count shifted actual input
produces `11194AE118004CDA6D9D61614D3105D1AFE1CB328DACC11687731541A1312ACD`
and is rejected. The independent small host vector uses BinaryWriter rather
than copying the production incremental-hash implementation.

Raw matches at 0x4473ef and 0x4b9cb1 are operands of JL at 0x4473ed and MOVZX
at 0x4b9cad. Their proposed return RIPs 0x4473f1/0x4b9cb3 must not become
syscall authority merely because bytes before them are 0F05. The reviewed index
contains only the 166 decoded sites. It does not prove all possible control
flow, generic x64 decoding, or any actual guest path.

Final NativeAotHelloProgram.cs raw SHA256:
`E9A89198D3F62CDE34D561A4EDF4677E85308FC140513BE9072B56970A50BEED`.
