# Step 1059 - Bounded x64 one-frame virtual unwind

## Summary

Implements #578's host interpreter prerequisite for #90. It reads admitted
original metadata and stack bytes and returns one caller's nonvolatile integer
and XMM values, RSP and raw RIP. It does not restore CPU registers or execute
exception handlers. Merge/closure still waits for accepted #89/#574 integration.

## Why

Metadata lookup and type matching do not recover a caller frame. This leaf
implements that operation without changing the existing parser or EFI profile.
Development uses reviewed base `0ef4fe913471d32e5890a5c6b2691da572f30b52`;
the pending upstream acceptance is not represented as complete.

## Failures

No build or test failed. Before compilation, review found that SET_FPREG must
use the original fixed frame base rather than a candidate register already
restored by SAVE_NONVOL. The correction and a distinctive admitted-shape test
were included in the only compiled version. This is a defensive CLROS subset
rule, not a claim that the pinned compiler emits that exact prolog or that the
operation is a complete RtlVirtualUnwind replacement.

Two read/wrapper errors did not affect code or evidence: a source-inspection
command used a nonnumeric Select-Object count; and the parent checked a stale
LASTEXITCODE after the PowerShell step allocator had already emitted PASS.
The step1059 reservation was verified directly and was not rerun.

## Deferred work

Only v1 non-chained normal frames are supported. The epilog recognizer admits
bounded ADD/non-SIB LEA/POP/RET/F3 RET suffixes; unsupported transfer/prefix
forms, machine/chained frames and cross-image returns reject explicitly.
Every error returns a zero payload. Epilog success intentionally supplies no
handler establisher frame (`EstablisherFrame=0`).

Original storage must remain exclusively stable and mapped. Numeric bounds
and host contexts do not authenticate a live processor capture, instruction
boundary or compiler frame. Actual register capture/transfer, live stack
binding, unsupported unwind forms, language-specific EH records/search,
rooted exception objects and compiled catch/finally/rethrow remain #90 work.
