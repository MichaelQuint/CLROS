# Step 1012 - Prepare terminal control flow for the first real firmware exit

## Summary

Add `FirstOptRealExitBootServicesTransition.AttemptAndTransfer` as the #64
coordinator around the accepted final-map and two-attempt stale-key retry core.
Every returned value represents refusal or failure. After successful exit it
records BootServicesExited, preserves the result, clears retained firmware
callbacks and transfers once to the owned continuation. An unexpected return
from that continuation enters a callback-free terminal loop, never the EFI caller.

## Why

The real-exit adapter must not accidentally resume a firmware-backed error or
return path after ExitBootServices has succeeded. This control-flow boundary can
be prepared separately while #552 keeps the collector integration source frozen.
The complete #64 live-transition scope is unchanged and remains open.
