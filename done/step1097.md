# Step 1097 - Compiled tooling and test-suite migration

## Summary

Completed the C# implementation of the tooling migration begun in step1096.
Maintained host automation and embedded fixture scripts are replaced by .NET 10/
C# 14 console commands and typed APIs. The final frozen-input fast and full host
runs and all 39 declared real guest captures pass.

## Why

The previous full host run took 5,607.843 seconds. Repeated PowerShell startup,
source extraction and native publications made implementation feedback slow.
Whole-test-file hashes and copied counts made unrelated edits repeatedly fail
the same assertions. The new fast lane runs behavioral checks without native
publication, while the full lane retains actual compiler, verifier, artifact,
process-lifetime and negative-input coverage.

## Files changed

- `tools/OS.Tooling`: EFI producer/preflight/verifier, QEMU/qcow2 orchestration,
  transcript validation, backlog sync, CI/baseline evidence, libvirt, package
  publishing, repository checks and atomic step allocation.
- `tools/OS.QemuCapture`: the original raw capture shim is a reusable compiled
  console application. `OS.QemuRunner` and capture reuse `QemuContracts`.
- `tests/OS.HostTests`: explicit discovery, bounded parallel fast workers,
  exclusive native workers, stable markers, streamed logs, failure aggregation,
  receipts and source freshness. Script-extraction fixtures call actual C# APIs;
  independent numeric/byte vectors and malformed-input controls remain.
- `EfiContracts` partials and `QemuContracts`: shared reviewed source/package/
  native-object identities, probe/compile inventories and protocol records.
  Counts derive from inventories; raw provenance remains distinct from normalized
  source-content checks. Another test's source hash is not a behavioral oracle.
- CLI and host-runner build-input manifests reject changed, missing or newly
  introduced source, with exact-source relocation for controlled native clones.
- Remove maintained PowerShell scripts and the app package script; update the
  solution, CI workflow, canonical backlog callers, agent guides and operational
  documentation. Historical step files remain unchanged.

## Failures

Migration verification exposed and repaired omitted profile prerequisites,
descriptor marker ordering, module/firmware parser parity, diagnostic-output
differences, and remaining test-source hashes. A producer timed out after native
link completion because a tool child remained alive; restoring the original
explicit post-root-exit cleanup policy retained exit codes and reduced the native
publish stage from that 300-second timeout to approximately 5–6 seconds.

Independent review also found a general worker descendant-lifetime gap and a
scheduler callback-failure drain gap. The launcher now confirms process-object
termination as well as an empty job; callback failure retains its original error
only after cleanup. The scheduler drains active work and cancels future work when
termination cannot be confirmed. Original process controls and the new lifecycle
matrix pass, including immediate exclusive reopening of child-held files.

The first parallel fast run exposed real producer/preflight controls incorrectly
classified as fast, a missing nested suite start marker, and trusted protocol
records incorrectly split on embedded commas. Those tests retain their original
assertions: producer work is exclusive, markers pair exactly, and trusted records
remain intact while user marker lists retain comma parsing. The corrected fast
run passed 3,042 checks in 37.476 seconds. Final results below supersede this
intermediate measurement if later source changes require another run.

The first full run stopped early while writing its progress receipt with a
Windows access-denied error. It did not reach native acceptance. The shared
atomic receipt writer now applies a bounded retry for transient Windows file
sharing errors; persistent errors still fail and retain complete diagnostics.
The failed attempts remain in `artifacts/test-migration/fast-r01-failures.log`
and `full-r01-receipt-failure.log`.

The completed frozen-input audit (`full-r02-audit-failures.log`) took 1,380.007
seconds and executed 3,954 checks. Its five failed fixtures exposed four obsolete
module-initializer predicates across three classes, the translated linked-source
diagnostic, and a CRLF-only project-content pin. The replacements use actual
compiled discovery, retain the original diagnostic category, and normalize only
reviewed content comparisons. Exact raw before/after snapshots and link-evidence
hashes remain required. This failed audit is not full acceptance.

Final review found legacy grouped cases bypassing `--case` and several copied
reviewed generator hashes. Fourteen leaf helpers, 32 standard-library cases and
20 manual aggregate entries now route through `HostCheck`, preserving their
assertions and original marker names. Selected/omitted controls verify actual
execution. Shared whole-object expectations have one reviewed owner; conditional
child controls receive these values from their parent. Independent byte/ABI
vectors and historical evidence remain separate.

The first guest-executor attempt correctly failed the producer's canonical
output-directory guard before publication or boot. The ignored executor's
paths were corrected; the production guard was unchanged. The failed receipt
remains at `artifacts/test-migration/real-qemu/20261009T121632320Z-3c9ac1f0`.
The subsequent complete 39-entry guest run passed without production changes.

## Evidence boundary

Controlled fixtures and dry runs are not guest proof. Only an unfiltered full
host run may emit `TEST_PASS host.tests`; fast and focused runs have distinct
terminal markers. New QEMU evidence requires a fresh source-bound image, real
QEMU/OVMF execution and captured serial/summary records. This change does not
advance a numbered OS completion gate or claim cloud/production readiness.
