# Step 1238 - Scheduler-backed blocking pipe consumer

## Summary

Development stage for #686/#733, parent
`a1ba1d722f02291d4f7a36b96bbe37fa75ff16b0`, draft PR #732. LAN repository
ID9 and both live claims were read back. The exact new partial/test paths and
reuse of the descriptor test model were added to #733 and read back before
editing. Compiled OS.Tooling reserved this step. All acceptance issues remain
open; no evidence-reviewed closure marker is added.

LinuxThreadServices now explicitly attaches a descriptor owner before Start.
Blocking pipe read/write retains a stable, noncopied operation on the original
open description and uses the existing KernelThreadTable BeginWait/Park/Wake
sequence. Real data, capacity and peer-close changes wake matching operations.
Completion retries that description even after the fd closes and is reused.
Scratch is cleared before parking; each actual user copy checks the current
mapping. No second scheduler, allocation or busy polling is introduced.

## Why

The pinned .NET11 payload's SigHandler worker blocks on a pipe; the old M16-007
nonblocking pipe contract cannot supply its scheduler behavior. Descriptor fd
references and pending operation borrows now have distinct lifetimes. Only the
last combined reference closes an endpoint; the pipe buffer is released and
scrubbed after both endpoints close. Raw descriptor dispatch/End refuses an
attached owner so it cannot bypass the wake/reference transaction.

Writes larger than PIPE_BUF retain committed progress across capacity waits;
an error after progress returns only that prefix. Originally short writes
remain atomic. Copy-out failure preserves queued bytes. EOF, ignored-SIGPIPE
EPIPE, changed shared nonblocking flags and shutdown drain are explicit. This
mechanical slice requires SIGPIPE already ignored; delivery/EINTR/restart is
still #687. Blocking writev remains unsupported.

## Files changed

- LinuxDescriptorServices.cs and new LinuxDescriptorServices.Pipes.cs:
  retained-description accounting, exclusive attachment and checked operation
  start/retry/release. LinuxPipe.cs adds an internal streaming append for an
  originally large write; its existing public behavior is retained.
- LinuxThreadServices.cs, LinuxThreadServices.Futex.cs and new
  LinuxThreadServices.Pipes.cs: explicit pipe admission, separate wait-source
  ownership, descriptor dispatch, actual wait completion, exit/reap/release
  cleanup and disjoint descriptor/futex storage checks. Instance fields remain
  in the main partial declaration.
- New LinuxBlockingPipeTests.cs; existing descriptor/thread test models are
  reused without changing old descriptor assertions. Two normalized EFI source
  pins, docs/app-model.md and this step. The new Linux thread/pipe consumer is
  still not linked into EFI or the native gateway.
