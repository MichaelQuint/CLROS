## What changed and why

Issue #582 now executes one real compiler throw across a non-inlined Thrower
frame into Catcher's typed base-class clause, then resumes the actual compiled
continuation. This crosses the earlier host-only metadata/interpreter boundary.
The disabled child reuses the original module, allocator, explicit receipt root
and owned stack. The object survives the prethrow collection; dispatch and catch
perform no allocation or collection. A C# COFF generator supplies the Win64
capture, catch-call and continuation bridge without first-party native source.

The implementation captures real raw RIP/RSP and nonvolatile GP/XMM state,
uses raw RIP for unwinding and RIP-1 for EH containment, selects the returned
Caller context rather than Thrower's EstablisherFrame, validates exact original
ILC/COFF contributions and the funclet-returned continuation, and restores the
post-catch state. Unsupported geometry, DF/CET state and authority reject.

fields remain false. The existing freshness guards now bind the actual
