# Step 1014 - Adopt owned descriptors through a compatible IDT bridge

## Summary

Extend #64's permanent-CR3 continuation with descriptor preparation and actual
LGDT/LTR/LIDT/segment-load/readback instructions. Build a temporary owned IDT
whose gates retain the current firmware CS selector and use IST=0. Add an
equivalent code descriptor at that selector in the owned GDT. This keeps the
bridge gates usable on both sides of LGDT without relying on an unloaded TSS.

After successful EBS, the emitted continuation loads the bridge IDT, owned GDT,
DS/ES/SS, owned TR and final IDT. One local far transfer refreshes CS to selector
8. It checks all ten bytes of GDTR/IDTR, TR, busy-TSS state and CS/DS/ES/SS before
permanent CR3 adoption and the later owned diagnostic call. It has no near return
or firmware-CR3 restoration path. Explicit failed comparisons still halt.

## Why

Step1013 left descriptor installation as a caller precondition. Installing
incompatible GDT/IDT pairs independently creates a transition window in which an
exception could select the wrong descriptor. The bridge removes this mismatch
from the emitted sequence while retaining the requirement that every handler,
table, stack and code/data range is actually owned and mapped. Firmware descriptor
state stays intact during the earlier final-map/ExitBootServices calls.

## Failures

The first independent-review assertion expected LLVM to print MOV DS/ES/SS with
an AX operand. LLVM prints EAX for the unprefixed segment-load encoding used by
the accepted M02 sequence; the selector still comes from its low 16 bits. The
review expectation was corrected without changing emitted code. Builds and
focused checks passed. UEFI overview pages were unavailable to the web reader;
this is not treated as new platform-execution evidence.

## Deferred work

No privileged instruction was executed by these host tests or decoding checks.
The bridge's actual terminal handlers, complete reachable stack bounds and both
roots' complete retained mappings must be reviewed and exercised in the real EFI
adapter. Descriptor preparation checks encodings and pointer ranges; it does not
authenticate handler code, prove page ownership or map guard/IST pages. During
the bridge, fault/NMI handlers use the current owned stack, so its declared stack
reserve must cover that path as well as the eventual diagnostic. After final
LIDT they use the prepared final IST routing. All such handlers must terminate.

This addresses the descriptor-installation precondition recorded in step1013;
it does not claim general asynchronous handoff safety or eliminate the need to
validate the actual firmware environment. #64 still needs authentic firmware
binding, owned-stack/arena preparation, default-off EFI wiring, owned COM1 markers,
live negative controls, native mapping/stack review, the integrated common gate
and real QEMU/OVMF proof. Canonical integration docs will be updated when #64 owns
that lane. The issue remains claimed/open and PR554 draft. No all-adapter firmware
invalidation, hosted .NET, Kestrel, cloud or production claim follows.
