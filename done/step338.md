# Step 338 - Backup GPT Caller-Buffer Parser

## Summary

Added backup GPT parsing to the caller-buffer `GptPartitionTableParser` path and
proved it against both synthetic host buffers and raw images generated by
`tools/OS.ImageBuilder`.

## Why

Storage readiness needs a CRC-valid backup GPT contract before package and
manifest loaders can grow fallback behavior. The parser now has an explicit
backup-header entrypoint with deterministic status failures for invalid backup
metadata while preserving caller-owned buffer behavior.

- `src/OS.Kernel/Storage/GptPartitionTableParser.cs`
- `tests/OS.HostTests/GptPartitionTableParserTests.cs`
- `tests/OS.HostTests/ImageBuilderTests.cs`

## Deferred work

- Package and manifest loaders still use the primary caller-buffer GPT path only.
- Backup GPT fallback in ESP/package loading remains a separate storage slice.
- The legacy block-device `GptParser` still does not enforce GPT CRCs.

## Evidence boundary

This proves host-side parsing and generated-image readback for backup GPT
headers and backup partition-entry sectors. It does not prove live disk I/O,
real virtio-blk reads, boot-time backup GPT fallback, or cloud-provider image
readiness.
