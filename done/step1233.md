# Step 1233 - Mechanical wait/TLS worker bytes

## Change and ownership

Implements the first concrete shared-integration stage of claimed #733 for
#191/#192 and their NativeAOT consumers, under draft PR #732. Parent source is
`086dd7e459529cc5deac2198a68ea52caadf7d48`. The LAN issue was created after open
issue/claim review and read back; its exact scope was extended before editing
the existing program helper/test-plan surfaces.

`ThreadWaitProgram` reuses the existing driver, first-entry/return, recovery,
IRQ helpers and context-switch stubs. It independently encodes four fixed worker
CALL actions followed by normal returns (17/23). Optional actual FS:[0]/GS:[0]
loads put TLS data in captured R12/R13 at every action. Plain wait mode has
fixed executable NOPs in those slots. All continuations retain the same Win64
stack discipline; the separate 512-byte IRQ region remains independently owned.

Shared input admission and infrastructure encoding are internal helpers. Original
public `KernelThreadProgram.Emit/Verify` retains its original worker template and
byte checks. Every component is dry-validated before unpublished output writes;
no mapping, publication, transfer, IRQ or TLS authority is granted by emission.
