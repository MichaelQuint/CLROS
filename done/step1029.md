# Step 1029 - Correct native first-exit admission and observe development markers

Issue #64 / draft PR554. Isolated development evidence; canonical acceptance
and the completion gates remain pending.

## What changed and why

- Supply the compiler-required `__security_cookie` using the existing no-CRT
  EFI anchor convention. The first native link exposed the missing symbol.
  Its fixed RX bytes are readable storage, not randomized security hardening.
  Reject the independent-endian profile to avoid its duplicate cookie export.
- Add bounded pre-entry preparation checkpoints and the observed table memory
  type to the existing failure line. Firmware output remains confined to failure
  before owned entry. Checkpoint 82/type 3 identified OVMF's Boot Services table
  inside an EfiBootServicesCode descriptor. Table admission now accepts service
  code/data types 3..6 while retaining exact single-descriptor coverage, header
  bounds, owned-map checks and downstream table CRC/identity validation. These
  firmware pages are not added to retained mappings. EDK2 defines its Boot
  Services table as DXE core static data:
  https://github.com/tianocore/edk2/blob/master/MdeModulePkg/Core/Dxe/DxeMain/DxeMain.c
- Correct installed descriptor validation to require consumed state 2. Native
  adoption already records 2 before loading descriptors; the validator and host
  fixture incorrectly retained prepared state 1. Update the existing fixture to
  model consumption and reject otherwise-complete installed observations in
  state 1. Fresh descriptor admission still requires 1.
