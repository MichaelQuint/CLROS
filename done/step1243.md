## Why

The process consumer needs a continuing native owner rather than another
scheduler. Its driver checks actual CPU/PTE/code state before each dispatch,
compares the emitted supervisor witness after return and confirms the handoff
before reclamation. Shutdown routes cancellation through genuine worker
continuations. Untimed waits without a runnable peer cannot busy-loop: bounded
failure requests shutdown; unresolved native ownership retains the reservation.

Reap scrubs the real context, usable kernel stack and process slot before reuse.
The independently retained 16-KiB code snapshot remains valid while the scrubbed
descriptor cannot pass program verification. The owner reads the actual advanced
kernel generation, initializes its context, changes only code page0 from RX to
RW/NX, re-emits its 256-byte entry, restores RX and validates all other code bytes
before publishing the prepared worker. It introduces no writable executable
mapping. Exhausted/retired generations fail closed rather than inventing a handle.

The IRQ path borrows IST4, a guarded four-page interrupt stack ending at pool
page62 and a copied IDT at page63. It admits only the emitted supervisor
STI/HLT/CLI frame, with actual kernel CR3, current IF/DF clear, saved IF set and
the original CPU/descriptor envelope. A separate one-entry deadline queue holds
the retained supervisor identity at the next IRQ epoch. SchedulerTimer
acknowledges and stops that genuine one-shot; its queue is drained before
LinuxThreadServices.AdvanceFutexClock reads owned HPET nanoseconds. IRQ epochs
never become Linux time. Reload2,000,000 and a 128-epoch bound are counts, not
calibrated durations. No asynchronous user preemption is implemented.

Cleanup restores APIC before dropping the IRQ-stack/IDT borrow, requires empty
actual process/table ownership, detaches the memory guard, closes descriptors,
restores original pool PTEs and checks scrubbing. The firmware reservation stays
retained. Unsafe hardware/transfer/reap failure cannot authorize release. Entry
preconditions authenticate the fixed owner and complete unpublished pool before
any cleanup or write. The future caller must explicitly select ResumeUser mode.
