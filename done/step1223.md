The host harness checks inputs before launch/reuse and after every
result, including failed and fresh native fixtures. Detected changes latch the
run invalid, cancel scheduling, drain active workers through existing bounded
process cleanup, and invalidate current-run checkpoints immediately. Late
completion cannot recreate a reusable pass. Ordinary failures with unchanged
inputs retain existing continuation behavior.

Boundary checks use file metadata, hashes for changed files, source/repository
inventory and environment identity. Exact byte checks remain separate; final
validation compares the original recorded input snapshot unconditionally,
including the producer DLL. Fixture text and raw hashes come from the same byte
read. Restoring bytes cannot rehabilitate an already-invalidated run.
