# Step 1270 - Runtime output framing and actual wait observations

## Summary

Implement two prerequisites for complete focused NativeAOT runtime consumers:
bounded raw stdout decoding and native observations of the actual retained
wait source/deadline/sequence. All 67 final focused checks across 13 fixtures
pass with zero reuse/failures, alongside combined no-stdlib C# compilation.

## Why

Runtime stdout can span arbitrary writes. Validate original byte counts and
kernel CRLF before normalizing payload newlines or accepting complete output.
Timed futex wake ordering cannot be proven from a timespec pointer or timer
ready count. Expose the existing owner's actual deadline rather than infer it.
Neither prerequisite alone establishes a complete guest protocol or execution.
