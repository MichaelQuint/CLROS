# Step 1412 - Pre-entry UTC admission fault controls

## Summary

Continue the owned #220/#221/#222/#759/#223 batch under #737. Add default-off
copied-source unavailable/invalid UTC controls for #759 and a separate strict
rejection-capture inspector. This is implementation with focused host evidence;
all five issues remain open, without new guest or native qualification.

## Why

UTC must fail closed before service readiness. Host clock model tests alone do
not exercise the EFI preparation branch, owner release or absence of workload
entry. The diagnostic selections now make those observations capturable without
turning a rejected preparation into ordinary web/QEMU smoke success.

## Files changed

- Probes.cs and OS.csproj declare mutually exclusive M16019Unavailable/Invalid
  defaults, each requiring the existing M10004 web profile. EfiProfile supplies
  that parent chain and rejects conflicting/explicit-false selections.
  EfiContracts and Admission record the symbols and updated project-only identity.
- EfiEntry.Realtime.cs first requires actual successful GetTime, a bounded
  monotonic bracket and a valid copied calendar. It then substitutes only the
  copied status (EFI_UNSUPPORTED) or month (zero). Both use the ordinary shared
  admission helper. Refusal leaves the realtime owner unavailable and returns
  through the existing checkpoint96 pre-entry cleanup. EfiEntry.cs emits the
  exact rejection observations after that cleanup and before the original
  preparation failure. Fault fields/writer exist only in fault selections.
- QemuProfiles.cs rejects either fault for ordinary smoke. The new
  QemuTranscripts.RealtimeAdmission.cs inspector requires a bounded, immutable,
  single-link capture; exact firmware prefix and parent records; exact package/
  startup release and closed handles; canonical fields; and the nine-row
  rejection tail through EOF. It reports observations only. Original source,
  native, image and owned-runner authority remain separate requirements.
- RealtimeAdmissionControlTests.cs adds six independent profile/schema/negative
  checks, including omitted/duplicate/extra rows, cleanup, source status, calendar,
  entry/readiness, memory type, canonical numerics and fake firmware refusal.
- Scoped M16-019 ownership metadata and existing app-model/Kestrel docs retain
  the development-only boundary.
