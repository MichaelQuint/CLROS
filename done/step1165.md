# Step 1165 - Implement bounded nested-EH search and bridge leaves

## What changed and why

Begin the owned #90 batch #638-#640 with two small reusable leaves. The
allocation-free dispatch policy consumes up to four physical decoded clauses
and matching retained-object predicate receipts. It searches typed catches in
compiler order, validates the complete table/topology and returns at most two
strictly nested exceptional cleanup targets before the selected catch. No
handler address is exposed on failure. Unsupported filters/group markers,
crossing/reversed/equal cleanup ranges and capacity violations are rejected.

The separate nested bridge definition carries a 272-byte POD transfer in an
856-byte Win64 frame. It restores selected nonvolatiles before each cleanup,
validates each return before the next transfer and preserves the actual
catch-produced continuation/register/control state. The original three EH
definitions retain their exact reviewed object bytes. This definition is not
linked or enabled yet; integration #640 owns the later default-off profile.
