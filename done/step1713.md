# Step 1713 - Dynamic reservation and entropy source discovery

## Summary

The reservation-subtractor fixture now derives its no-stdlib dependency slice
from actual compiler inputs. The entropy source fixture follows logical types
and a bound call target after the structural split. Both pass focused validation;
an intermediate entropy failure remains preserved.

## Why

Source moves must not require positional Compile lists, adjacent declarations
or filenames in host checks. Discovery supplies inputs and bindings; independent
layer restrictions, byte identities, ABI values, failure semantics and marker
expectations continue to decide acceptance.

## Files changed

- BootReservationSubtractorTests and its SourceDiscovery/SourceControls partials.
- M03FirmwareEntropySeedEfiIntegrationTests and its SourceDiscovery partial.
- EfiContracts.HostOracles, README, host requirements, repository audit and this step.

Reservation discovery starts from five independent logical ABI types in the
actual host kernel compilation, retains complete dependencies, rejects foreign
layers and joins every selected production byte to the actual EFI inventory.
The original local shim, probe, behavioral methods, marker registration and SDK
no-stdlib recipe remain intact. The final reduced compilation is checked with no
framework references before generating Compile items.

The shim selector resolves the bound framework File.WriteAllText call whose
bound Path.Combine destination is NoStdLibShim.cs. It requires one call and a
constant body. It no longer chooses the first raw string literal. Controls cover
partial/moved declarations, unrelated literals/writes, missing/duplicate or
foreign writers, hidden forbidden partials, wrong ABI constants, nested callers,
missing dependencies, foreign layers, EFI-byte drift and changed shim types.

Entropy keeps the original historical raw-byte pin and independently verified
successor type identities. Its expected canonical hashes were derived from the
retained pre-split original only after complete declaration/token/order review.
Source ownership is discovered by metadata type identity. UTF-8 without a BOM,
using all LF or all CRLF, is admitted only if the actual original-byte hash
matches that encoding and the canonical type hash matches its reviewed pin.
BOM, UTF-16, mixed-newline or changed content cannot gain admission by decoding.

The entropy entry check resolves the unique caller of FirmwareEntropyCapture.Run
and requires direct ownership by EfiEntry. Original terminal failure behavior,
pointer/publication predicates and raw forbidden-source exclusions remain.
The separate Native capture fixture's fixed source list is still unfinished.
