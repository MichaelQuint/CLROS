# Step 1001 - Prepare bounded stale-map-key retry

Add the host/no-stdlib portion of M03-006 (#63) on the preparatory M03-005
branch. This is separate from the running EBS/GC acceptance candidate; #63
remains blocked on accepted #62 and no shared EFI integration lane is claimed.

`src/OS.Kernel/Boot/BoundedRetryStaleKeyStatus.cs` composes one or two final-map/
exit windows using separate retained states and the same already-owned buffer.
Every exit attempt uses its own newly captured key. Only a returned exit call
with exact `EFI_INVALID_PARAMETER` permits the second capture. Other exit errors,
capture failures, rejected admission and invalid metadata stop immediately.
The result preserves the last window/status and distinguishes windows started
from exit calls. The outer state rejects reentry/reuse and buffer overlap.
There is no buffer growth, allocation, logging hook or unrelated firmware call.

Other changed files: the matching HostTests initializer, `docs/boot.md`,
`docs/efi-build.md`, and this step. No production EFI, publisher or profile
source changes are included.

## Boundary

Controlled host callbacks and no-stdlib IL are not firmware execution evidence.
The caller must serialize and retain zero-initialized state without copying or
resetting it, supply authentic mapped memory/pointers, and invalidate firmware
access after a future real successful exit. Callback exceptions and hostile
mutation are not contained. This does not adopt CR3, change firmware mode,
validate descriptor contents, implement post-firmware diagnostics, or establish
hosted .NET/Kestrel, device I/O, cloud support or production readiness.
