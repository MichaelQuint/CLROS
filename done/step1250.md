## Why

Upstream NativeAOT activation uses a directed real signal. Successful tgkill
must retain a live target event rather than discard it or invoke a callback in
the kernel. Pending ownership must not leak across kernel generation/TID reuse,
and blocked signals must survive until the actual target unmasks them.

Standard signals coalesce; Linux's synchronous-class numbers take priority,
then the lowest standard number. Four realtime events per actual generation
retain repetitions, priority by number and FIFO order within the same number.
Capacity exhaustion returns EAGAIN unchanged. All admitted directed events have
SI_TKILL, sender process PID and uid0; no arbitrary sigqueue payload is accepted.

Masking retains pending work. Unblocked ignored signals are discarded on send;
blocked ignored signals remain because disposition may change before unmasking.
Setting an ignored action flushes that signal on every actual thread before
old-action copyout, including the committed-EFAULT case. Selection consumes only
successful/ignored/fatal delivery and invokes at most one user handler via the
owned image. Rejected/unsupported delivery retains the entry. Actual reap
scrubs all pending and frame metadata; Linux TIDs do not recycle in this owner.

tgkill uses low Linux int arguments, validates positive group/TID and actual
process/kernel generation, and supports a signal0 existence probe. A matching
exiting task acquires no new queue lifetime. SIGKILL stages real process-wide
shutdown137 and returns a terminal gateway action, bypassing queued/masked
handlers. Unimplemented default job control returns ENOSYS. An unmasked,
nonignored send to a staged wait also returns ENOSYS before queue/wake mutation:
EINTR/restart is not implemented yet. Masked sends may remain pending across a
real futex wake/completion and later deliver after unmasking.
