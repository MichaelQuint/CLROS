# Step 1013 - Emit the terminal owned-CR3 continuation

## Summary

Extend #64's existing terminal coordinator source with a 333-byte x64 continuation
emitter and its 112-byte caller-owned context. The continuation requires the
coordinator's successful-exit state, exact firmware CR3/CR4, Win64 stack alignment,
declared diagnostic stack headroom and two stack canaries. It clears CR4.PGE,
permanently loads the owned root, checks CR3/CR4 readback and both canaries again,
and calls the supplied owned diagnostic once. It never returns or restores
firmware CR3. Explicit refusals and an unexpected diagnostic return halt.

## Why

The accepted M01 transition is reversible. Reusing its restoration path after
real ExitBootServices would violate the permanent handoff requirement. This
small emitter supplies the actual privileged instruction sequence independently
of the frozen collector integration tree. Its caller still owes the full live
mapping, descriptor, firmware-entry-point and diagnostic preparation.

## Deferred work

This is an instruction emitter and host admission check, not real firmware exit
or guest acceptance. The original context and code must be retained exclusively
and authenticated by the adapter. The supported preparation slice deliberately
uses low canonical identity addresses, page-table roots below 4 GiB and CR4 bits
0..10 with PAE set; PCID, LA57 and CET are outside this emitter's admitted slice.
Only stack bounds/canaries and control-register readback are checked here.

Before entry, the adapter must validate the complete essential mappings, install
and read back owned GDT/TSS/IDT/IST, retain copied ACPI/allocator/panic state and
ready owned COM1. CLI does not mask NMI or exceptions. The diagnostic's complete
reachable stack bound must be reviewed, and successful post-EBS markers must not
be emitted until descriptor/map/canary observations are accepted. A fault caused
by an invalid mapping is not an explicit guard refusal and requires owned fault
handling. This source is not yet admitted to or called by the EFI artifact.

#64 remains open/draft for authentic firmware binding, default-off integration,
negative controls, actual NativeAOT/owned mapping review, the integrated common
gate and real QEMU/OVMF proof. No all-adapter invalidation, hosted .NET, Kestrel,
cloud support or production readiness follows from this evidence.
